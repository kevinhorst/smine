# Plan format viewer fixes — Change Plan

route: `change`

## TLDR

- The plan format mandates raw-HTML anchors and row-level fragment links; Claude Code's plan viewer renders the HTML literally (`<a id="d1"></a>D1` in table cells) and never navigates fragments — anchors are dropped, references become section-slug links (`[D6](#decisions)`): clickable in VS Code via heading auto-anchors, clean styled text in the Claude viewer.
- `Open questions` sits second-to-last in the canonical section order; as the index of what the user must answer it moves directly after `Decisions`.
- Hot-item UI evidence becomes a screenshot of the **actual UI under design** (captured from the running app), stored under the plan's design dir, and every UI-touching Changes entry references its screenshot via a `ui:` line.
- Touches: `context/rules/plan.md`, the `planformat` ACDSL verifier + fixture, `context/actions/concepting-local.md` (ACTION-CONCEPT-HOT-007), the fdesign and fmt skills, regenerated `context/context.json`.

## Context

- **Problem:** plans produced by /fdesign are unreadable in Claude Code's plan viewer — anchor HTML shows verbatim, links are dead (user screenshot); Open questions hide at the bottom; UI evidence is mockups without a tie to the code that changes the UI.
- **Cause:** RULE-PLAN-018 (context/rules/plan.md:45) mandates `<a id="f20"></a>` anchors + fragment links; RULE-PLAN-002 (context/rules/plan.md:13) orders Open questions 19th of 20; ACTION-CONCEPT-HOT-007 (context/actions/concepting-local.md:26) accepts any "rendered mockup or screenshot" with no capture source and no Changes-entry reference.
- **Constraint:** the section order is machine-enforced by the planformat verifier ([cmd/acdsl/verifiers/planformat/main.go:26](cmd/acdsl/verifiers/planformat/main.go)) — rule text, verifier, and skill template must move together.
- **Constraint:** `context/context.json` is generated by `cmd/rules` only (ACDSL-GOLANG-STATE-001) — rule edits require a regenerate, never a hand edit.

## Target state

- One source of truth per concern, three synchronized surfaces for section order: rule text (RULE-PLAN-002) ↔ verifier `canon` ↔ fdesign template — all carry `… → Decisions → Open questions → Baseline (verified) → …`.
- **Principle:** render for the weakest common viewer — the plan format uses only constructs GFM renders everywhere (no raw HTML except `<br>` in cells); navigation degrades to search on unique IDs. Mechanism: plain-text `F<n>`/`D<n>` tokens, markdown file links only.
- **Principle:** evidence over artifact — UI evidence is a capture of the real system, wired to the code that changes it. Mechanism: screenshot files under `plans/{slug}/design/ui/`, `![...]` embed in Hot items, `ui:` reference line on Changes entries.

## Behavior contract

- **Must not change:** TLDR-first and Changelog-exists checks; all other section-order relations; content-identity contract of /fmt; every rule not named in Changes; verifier CLI contract (args, output format, exit codes).
- **Intentional changes:** relative order of `Open questions` (DR2, verifier-visible); anchor/link prescription inverted (DR1 — old-format plans become /fmt-flagged, not invalid: the verifier never checked anchors); HOT-007 evidence requirement sharpened (DR3).
