the feedback loop

smine mines your own past agent sessions for evidence, turns the findings into proposals, and — once you vote — deploys the accepted ones as skill rules and context docs. The next session runs under the improved instructions.

The loop: sessions in your project repos → peek-mcp exposes them → the nightly smine run mines transcript batches (Sessions) → ranked proposals land in the store (Proposals) → you vote → the nightly apply stage implements accepted votes → sync deploys the result. The Routines page drives and monitors the nightly run.

Try it: run /smine in any Claude Code session — or finish the Setup tab and let tonight's run do it.

acdsl & the context system

Context docs are typed entries — ACTION-* (process directives), RULE-* (artifact-shape guides), FACT-* (repo facts) — deployed into your target repos so every agent session runs under them. ACDSL is the machine-checkable slice: one rule = identity + anchor + verifier + why, projected into governed files as comment blocks and executed as a deterministic gate. One rule source, two renderings — they cannot drift.

A minimal bootstrap is one rule line, its verifier registration and a pass/fail fixture pair:

// acdsl/rules.acdsl — one declaration line
//acdsl: ACDSL-MYREPO-001 verifier=no-todo anchor=^internal/.*\.go$ why=TODOs rot — track work in issues

// acdsl/registry.json — the verifier the rule names
{
  "no-todo": {
    "argv": ["grep", "-L", "TODO"],
    "timeout_s": 10,
    "description": "flags files containing TODO markers"
  }
}

// acdsl/testdata/ACDSL-MYREPO-001/{pass,fail}/ — fixtures proving the verifier

Try it: open Context, pick your repo and hit Sync — the gate slice ships with a prebuilt binary and the deployed read hook activates it automatically.
