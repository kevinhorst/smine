the feedback loop

smine mines your own past agent sessions for evidence, turns each finding into one implemented change — a skill rule, a context doc, a permission — and lets you accept the ones you want. The next session runs under the improved instructions.

The loop: sessions in your project repos → peek-mcp exposes them → the nightly smine run mines transcript batches (Sessions) → each change lands as one commit on the night's branch and the judge marks it ready or rejected (Proposals) → you pick a change onto main to accept it → sync deploys the result. The Routines page drives and monitors the nightly run.

Try it: run /smine in any Claude Code session — or finish the Setup tab and let tonight's run do it.

acdsl & the context system

Context docs are typed entries — ACTION-* (process directives), RULE-* (artifact-shape guides), FACT-* (repo facts) — deployed into your target repos so every agent session runs under them. ACDSL is the machine-checkable slice: one rule = identity + anchor + verifier + why, delivered to the agent as context when it reads a governed file and executed as a deterministic gate. One rule source, two renderings — they cannot drift.

A minimal bootstrap is one rule line, its verifier registration and a pass/fail fixture pair:

// acdsl/rules.acdsl — one declaration line
//acdsl: ACDSL-MYREPO-001 verifier=no-todo anchor=^internal/.*\.go$ why=TODOs rot — track work in issues

// acdsl/registry.json — the verifier the rule names
{
  "no-todo": {
    "argv": ["grep", "-L", "TODO"],
    "timeout_s": 10,
    "description": "flags files containing TODO markers"
  }
}

// acdsl/testdata/ACDSL-MYREPO-001/{pass,fail}/ — fixtures proving the verifier

Try it: open Context, pick your repo and hit Sync — the gate slice ships with a prebuilt binary and the deployed read hook activates it automatically.

proposals

Proposals are the mining output: one card = one change commit on a nightly branch, already implemented and judged. Pick a change onto main to accept it on the Proposals page, or reject it; a change you leave stays for the configured number of mined nights, then drops out and is listed under History.
