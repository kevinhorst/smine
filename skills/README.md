# Skills

Skill definitions, synced flat to `~/.claude/skills/<leaf>` and `~/.codex/skills/` by `cmd/sync/sync_skills.sh` — one direction only, the repo is the source of truth.

## Skill structure

- **Layout** (scanner: `cmd/sync/sync_skills.sh:130-149`):
  - a first-level directory containing `SKILL.md` is a skill;
  - a first-level directory without one is a group directory — its subdirectories containing `SKILL.md` are the skills;
  - the leaf directory name is the skill's identity (deployed as `~/.claude/skills/<leaf>`);
  - plain files at the `skills/` root (like this README) are ignored by sync.
- **Per-leaf files:**
  - `SKILL.md` — frontmatter `name`, `description`, `author`, `version`, optionally `allowed-tools` (the skill's permission manifest) and `acdsl-context` (context entries injected at invocation);
  - `changelog.json` — the only changelog (`{version, date, text}` array, newest first); frontmatter `version` must equal `changelog.json[0].version` (ACDSL-SKILL-001);
  - optional reference files the skill reads at run time;
  - optional `workflows/*.js` — orchestration scripts bundled with their fronting skill (see [Workflows](#workflows) below).
- **Body format:** typed entries (`**SKILL-<NAME>-<TOPIC>-NNN** [class] — statement`), gated by ACDSL-SKILL-005 and rendered by `rules render-skill`. Authoring doctrine lives in [AGENTS.md](../AGENTS.md) § Skill authoring; skill registration and ordering in [README.md](../README.md) § Skill map.
- **Deployment:** sync is one-way, repo → home dirs, with per-directory pruning of skills removed from the repo and variant rendering via `--variant`.

## Workflows

Workflow scripts for the Claude Code `Workflow` tool: deterministic multi-agent orchestration. A script is plain JavaScript, but it does not run under Node — the harness executes it in a sandboxed interpreter with no filesystem, network, or Node API access. The script is pure control flow; all real work happens in the subagents it spawns.

### Invoking a workflow

Convention in this repo: a workflow is bundled with its fronting skill at `skills/<skill>/workflows/<name>.js` and is invoked **by path** — `Workflow({scriptPath: '<skill base dir>/workflows/<name>.js', args: ...})`, where the skill resolves the path against its own base directory (the directory containing its SKILL.md, stated at skill load time). Bundling means the script travels with the skill on sync and the invocation does not depend on the current working directory. The Workflow tool's name-based mode (`{name: ...}`) is deliberately not used: it only resolves scripts under `.claude/workflows/`, which this repo does not maintain.

Workflows run in the background: the tool returns a run ID immediately, progress is visible via `/workflows`, and the result arrives as a task notification. `args` is passed verbatim to the script as a global; pass real JSON values, not stringified JSON.

### Runtime model

Inside a script, the only orchestration primitives are:

- `agent(prompt, opts)` — spawn a subagent, await its result. With `opts.schema` (JSON Schema) the subagent is forced into structured output, validated and retried at the tool-call layer; the call returns a parsed object. Returns `null` if the agent is skipped or dies terminally.
- `parallel(thunks)` — run concurrently with a barrier: waits for all before returning. Failed thunks resolve to `null`.
- `pipeline(items, ...stages)` — per-item stage chains with no barrier between stages; the default for multi-stage fan-out.
- `phase(title)` / `log(msg)` — progress grouping and narration in the UI.
- `workflow(nameOrRef, args)` — run another workflow inline as a sub-step (saved name or `{scriptPath}`). Shares the parent's concurrency cap, agent counter, and token budget. Nesting is **one level only** — a child workflow cannot call `workflow()` again.
- `budget` — `{total, spent(), remaining()}`, the turn's token target from a user "+500k"-style directive. Hard ceiling: once spent, further `agent()` calls throw. Enables budget-scaled fleets and `while (budget.total && budget.remaining() > N)` loops. `budget.total` is `null` when no target was set — always guard on it, or the loop runs to the agent cap.

`agent()` opts beyond `schema`: `model` / `effort` (low–max) per call, `isolation: 'worktree'` (fresh git worktree, expensive — only for parallel file mutation), `agentType` (custom subagent from the Agent-tool registry), `label` / `phase` for the progress UI.

Constraints: concurrency is capped at min(16, cores−2) agents at once (excess queues) with a 1000-agent lifetime cap per workflow, `Date.now()` / `Math.random()` / argless `new Date()` throw (they would break resume), a workflow cannot pause for user input (why every workflow here is skill-fronted), and every script must start with a pure-literal `export const meta = {name, description, phases}` block.

Resume: re-invoking with `resumeFromRunId` replays the unchanged prefix of `agent()` calls from cache and only re-runs edited or new calls. Same script + same args = full cache hit.

### Dynamic shapes

"Dynamic workflow" is Anthropic's product name for the whole feature — the official docs apply it to every script, static or not. The useful shape axis (investigation 2026-07-24, `sessions/investigations/baseline-dynamic-workflows.md`): a workflow is dynamic-in-shape iff its set of `agent()` calls is not a pure function of script text + args. Tiers, with this repo's current placement:

- **T0 static** — agent set fixed at parse time: **unoccupied in this repo** (the former `analyze` is now the output-gated `session-mine`, T2).
- **T1 arg-shaped** — agent set computed from args before the first agent runs: `parallelize`, `railroad-review`.
- **T2 output-gated** — spawning depends on agent outputs: `session-mine` (the Route stage's batch list derives from the Mine agent's `batchesWritten`), `skillroutine-parallel-eval` (skips Manifest/Eval on zero survivors), `investigate` (Stage-B verifier shard count derives from the deduped claim count).
- **T3 iterative/convergent** — a loop predicate reads outputs or budget (loop-until-dry, budget loops, threshold-gated widening, adversarial multi-verifier voting): supported by the tool contract, **unoccupied in this repo**. railroad-review's approve-loop exists as the dispatcher-driven station protocol (one workflow invocation per round — human gates cannot live in a workflow); the workflow itself stays T1.

Determinism is orthogonal: even T3 stays resume-replayable — dynamic means data-dependent, never nondeterministic. No repo script yet uses `budget` or any `while` loop; railroad-review uses `pipeline()` for its per-direction lane→dedup→refute chain.

Authoritative sources, in order: (1) the live Workflow tool description in the harness — the only full API surface (budget, pipeline semantics, nesting cap, documented dynamic patterns); (2) the scripts here + git log; (3) https://code.claude.com/docs/en/workflows (caps, permission model, ultracode trigger, bundled `/deep-research`) — its Agent SDK TypeScript reference covers tool-invocation params only; (4) the claude-code CHANGELOG for when behavior changed (2.1.219 `workflowSizeGuideline`, 2.1.186 `agent({schema})` validation-loop fix).

### session-mine (skills/smine/smine/workflows/session-mine.js)

Run the whole smine retrospective: mine transcripts into batch reports (stage 1, `smine-batch`), then fan each batch out to all four dimension skills (stage 2). Fronted by the `/smine` skill (`skills/smine/smine/SKILL.md`), which parses the flags and (with `--no-batch`) resolves the target batches, then calls this workflow — invoke the skill, not the workflow, unless debugging.

- **args**: a JSON object `{nightly?, noBatch?, skip?, batches?, agents?}` — never a string. `skip[]` names dimension skills to omit (`--no-<dimension>`); `batches[]` is required when `noBatch` is set (the fronting skill resolves the unrouted batches from the ledger cursor). The script throws on a non-object, on `--no-batch` without batches, or when every dimension is skipped.
- **What it does**: **Mine** (skipped with `--no-batch`) runs one `smine-batch` agent, `--nightly` when set, returning every batch path it wrote in `batchesWritten`. **Route** iterates batches **sequentially** (per-dimension ledgers are shared across batches), and within each batch spawns the non-skipped dimension agents — `smine-skills`, `smine-routines`, `smine-context` in one `parallel()` barrier, then `smine-memory` after the barrier (it shares `proposals/context.json` with `smine-context` and must not write it concurrently; the batch JSON is emitted by `smine-batch` in the Mine stage, no longer a fan-out dimension). Each agent invokes its skill against the batch and is told to treat the skill's STOP-for-review step as "write outputs and return" (a subagent cannot pause for user review; the orchestrator reports instead).
- **Why the shape is safe**: within a batch the parallel dimensions write disjoint paths — per-dimension ledgers, per-dimension proposal JSON under `proposals/` — and the one shared file (`proposals/context.json`, written by both `smine-context` and `smine-memory`) is serialized by running `smine-memory` after the barrier; across batches the sequential loop prevents two batches' same-dimension agents from appending one ledger concurrently.
- **Returns**: `{mined, skippedDimensions, routed}` — `mined` carries `batchesWritten`/`sessionsMined`/`notes`; `routed` is one entry per batch `{batch, dimensions, failed}` where each dimension entry matches the result schema (`dimension`, `extracted`, `appliedOrProposed`, `outputPaths`, `notes`) and `failed` lists skills whose agent returned `null`. A failed dimension leaves its ledger unappended, so re-running the batch picks it up.

### investigate (skills/verdict/investigate/workflows/investigate.js)

Fan out N independent investigations of one open analysis/data question, re-verify every load-bearing claim against its actual primary source, then merge into one baseline with a refuted-hypotheses register. Fronted by the `/investigate` skill, which resolves the question, inputs, and fan-out width — invoke the skill, not the workflow, unless debugging.

- **args**: `{question, inputs, artifactsDir, priorArtifact?, investigators?}`. `question` and `inputs` are required strings (inputs must be fetchable — paths, live/archived URLs, prod-query targets); `artifactsDir` is a required absolute path to the session scratchpad outside every worktree, where investigator artifacts are written (never the repo); `priorArtifact` enters an existing analysis as investigation #1; `investigators` defaults to 3 (cap 8). The script throws if `question` or `inputs` is missing, if `artifactsDir` is missing or non-absolute, or if `investigators` exceeds the cap.
- **What it does**: Stage A (Fan-out) spawns `investigators` `general-purpose` agents in one `parallel()` barrier — each reads the inputs first, builds ranked hypotheses, and names the primary source for every load-bearing claim; siblings are never read (anti-anchoring). Stage B (Re-verify, v1.2) dedups the claims across runs (crediting every run that raised each claim), shards them into batches of ≤8, and runs one medium-effort verifier agent per shard in parallel; each fetches every claim's actual primary artifact — never a prior run's summary — and rules `holds | refuted | needs-measurement`, watching the full funnel. Shard verdicts are unioned into one verification register. Stage C (Merge) is a single high-effort agent producing the baseline with fact-vs-hypothesis labeling, the refuted-hypotheses register, credited net-new findings, and a discrimination plan.
- **Measurement gate**: `needs-measurement` claims are returned as `open_measurements` with concrete prod queries — a subagent cannot pause for the user, so the fronting skill surfaces them and re-invokes with `resumeFromRunId` once the user's results come back as binding facts.
- **Returns**: `{investigators, failed, verification, baseline}` — surviving investigator outputs, failed run ids, the verification register, and the merged baseline (each matching its agent's result schema). No surviving investigators returns `verification: null, baseline: null`.
- **Caveat**: investigator artifacts go to fixed filenames (`<artifactsDir>/inv-N.md`) — a second run against the same `artifactsDir` overwrites the previous run's reports. Move them before re-invoking.

### railroad-review (skills/quality/railroad-review/workflows/railroad-review.js)

Run one station-protocol round: fan a code review out to n lanes per railroad-review direction in isolated worktrees, collapse each direction's same-defect claims via a lightweight grouper, refute each claim at or above the severity threshold with a fresh agent, then consolidate everything in one station review with JSON+MD handoff artifacts and clean up the round's worktrees and branches. Fronted by the `/railroad-review` skill (multi-agent is its only mode — solo was removed in v7.0), which resolves the scope (committed range or a snapshot commit over uncommitted+untracked work), confirms the diff base, tiers the risk map, selects directions, and drives the station-protocol loop (human gate, rejection ledger, fix handoff, two consecutive clean rounds) around per-round invocations — the empty-diff guard, autonomous base derivation (never a prompt), snapshotting, and every human gate live in the dispatcher (the session running the skill); invoke the skill, not the workflow, unless debugging.

- **args**: `{base, head, baseCommit, headCommit, commitsAhead, scope?, riskMap?, chunks?, refute?, artifactsDir, diffFiles, round, directions?, lanes?, contextRefs?, focus?, laneModel?, laneEffort?, rejectedFindings?}`. `chunks` is the experimental chunked fan-out (SKILL MODES-005): an array of `{name, files[]}` partitioned by the dispatcher — lanes then run per direction × chunk and read only their chunk (`contracts` chunk-exempt); absent = unchunked. `refute` is the loglevel-style severity threshold (SKILL ROUND-007): candidates at that severity and above each get a fresh refuter — `blocker | major (default) | minor | nit | info`, or `none` for no refuter stage. `base`, `head`, `baseCommit`, `headCommit`, and `artifactsDir` are required strings (the confirmed diff base, the branch/commit under review, the resolved merge-base fork point of base and head — never the base tip — each worktree verifies as an ancestor, the resolved head tip each worktree verifies its HEAD against — both re-resolved by the dispatcher every round, and the absolute session-scratchpad path where artifacts land under `round-{r}/` — outside every worktree); `scope` defaults to `branch` — in the snapshot scopes (`wip`/`all`) `headCommit` is the dispatcher's snapshot commit descending from the checkout HEAD, which every agent worktree checks out as its one sanctioned checkout; `riskMap` is the dispatcher's per-file risk tiering (SKILL PROC-007), injected into every lane's attention briefing; `commitsAhead` must be a positive integer — an empty diff means stop and report, not fan out; `diffFiles` is the required changed-file list (`git diff --name-only <baseCommit> <headCommit>`, `paths`-narrowed), the coverage baseline; `round` is the required 1-based round number, namespacing artifacts and branch names. `directions` defaults to `code-style`/`correctness`/`critical`, minimum 1 (a single direction is a valid round), drawn from the eight known directions; `lanes` defaults to 2; `special-focus` requires `focus`; `laneModel`/`laneEffort` optionally override the lane agents' model/effort; `rejectedFindings` is the rejection ledger's content, injected into every lane and the station merge so rejected findings never come back.
- **What it does**: Fan-out runs a `pipeline()` over the directions — per direction, `lanes` `general-purpose` agents in a `parallel()` barrier, each in an isolated worktree at the review head tip with its branch renamed to `claude/railroad-{direction}-l{i}-r{round}-{hash6}` — review-only, no edits, no plan mode, blind to sibling lanes; each walks exactly its direction's checklist from the railroad-review SKILL.md, writes its findings as a JSON+MD artifact pair under `round-{r}/`, and returns structured findings plus `files_reviewed` (its coverage self-verification). The script deterministically diffs each lane's `files_reviewed` against its assigned list (chunk or full diff); each direction's claims then pass a lightweight grouper agent (text-only, no worktree, low effort) that groups same-defect claims — the script assembles the survivors deterministically (best-argued, max group severity, `merged_from` provenance, unplaced claims kept). There is no heavyweight direction-merge agent; cross-direction dedup belongs to the station. Refutation (pipelined per direction) hands each deduped claim at or above the threshold to a fresh refuter agent (worktree, branch `claude/railroad-refute-{finding-id}-r{round}-{hash6}`) briefed to refute it per the skill's Probe protocol — probe or cheapest artifact, both-directions test rule — returning confirmed | debunked | unverified with artifacts. Station merge is a single barrier agent in its own worktree forked after the fan-out from the dispatcher's checkout (so it re-verifies against the current tree — fixes may land out of band mid-review), branch `claude/railroad-station-r{round}-{hash6}`: unions all direction claim sets and dedups across directions (within-direction dedup already grouped), gives every finding exactly one disposition (confirmed | unverified | rejected-with-reason | duplicate-of | debunked), auto-rejects ledger matches, maps binding refuter verdicts into dispositions and adversarially re-verifies every claim without one — all severities — against the current tree (the second confirmation; deterministic via ACDSL probes where the repo supports it), assigns each confirmed finding a fix route (human | auto-fix | runner-fix), names permanent checks for recurring finding classes, runs build+tests once, unions coverage gaps, walks the definition-of-done, and writes the consolidated review as the round's handoff pair `round-{r}/review.json` + `review.md` with an APPROVE/CONDITIONAL/REJECT recommendation, undemonstrated high-risk suspicions escalated to the top and the claim funnel as the last line. Cleanup is a final agent in the dispatcher's checkout that invokes the agent-toolset `~/.claude/agents/tools/remove_agent_worktrees.sh --delete-branch` per expected `claude/railroad-*` branch — safety-gated, never forced; it runs on the all-directions-dead path too.
- **Returns**: `{base, head, scope, round, directions, lanes, refute, chunked, failed, abortedLanes, refutations, consolidation, handoff, cleanup}` — `failed` lists dead directions (all lanes lost); `abortedLanes` lists lanes that failed the premise check (`{direction, lane, chunk, notes}`); `refutations` flattens the refuter verdicts; `consolidation` carries dispositions, ranked_plan (routed), unverified, funnel, permanent_checks, build_test, debunked, resolved (out-of-band fixes with commit provenance), intentional_deviations, coverage_gaps, definition_of_done, recommendation, and the handoff paths; `handoff` repeats them as `{json, md}`; `cleanup` carries removed, skipped (script refusals, verbatim), and unattributed (worktrees at the review head the run cannot claim — reported, never touched). No surviving directions returns `consolidation: null, handoff: null`. A round with `consolidation: null` or non-empty `abortedLanes` is a failed round the dispatcher re-resolves and re-dispatches once.

### parallelize (skills/orchestration/parallelize/workflows/parallelize.js)

Fan one skill invocation across a `{model} × {effort} × {arg-variant} × replica` matrix in isolated worktrees, then consolidate into a grounded base plus cross-graft plan. Fronted by the `/parallelize` skill, which resolves the invocation and matrix spec — invoke the skill, not the workflow, unless debugging. Also nested by `skillroutine-parallel-eval` (the repo's only `workflow()` nesting).

- **args**: `{skill, skillArgs?, contextDoc?, models?, efforts?, argVariants?, replicas?, baseCommit}`. `skill` and `baseCommit` are required strings; empty matrix dimensions collapse to a single `null` entry (session model / inherited effort / `skillArgs`); `replicas` defaults to 1; efforts are validated against low/medium/high/xhigh/max. Cell count is capped at 16 — the script throws beyond that.
- **What it does**: Fan-out spawns one `general-purpose` agent per cell in one `parallel()` barrier, each with `isolation: 'worktree'` and per-cell `model`/`effort` overrides. Every cell verifies its worktree HEAD against `baseCommit` (mismatch → `baseline_mismatch_flag`), renames its branch into the `claude/parallelize-*` namespace, invokes the target skill unattended, and writes its deliverable to a file (`artifact_path`). Cells reporting contamination (read a sibling worktree) or baseline mismatch are disqualified. Consolidate is a single high-effort agent over the surviving artifacts: decision-point matrix, divergences, shared blind spots, the grounded base (the run that read the actual inputs wins), and a cross-graft plan.
- **Returns**: `{cells, disqualified, failed, consolidation}` — all finished cell outputs, the disqualified subset, dead cell labels, and the consolidation object. No surviving cells returns `consolidation: null`.

### skillroutine-parallel-eval (skills/skillroutine/skillroutine-eval/workflows/parallel-eval.js)

Pipe: nest the parallelize workflow over a fresh matrix, then score every surviving run with skillroutine-eval. Interactive only (needs the Workflow tool); the headless equivalent is the `skill-eval` routine (`routines/skill-eval/`, cells via `routines/_lib/matrix.sh`), which writes the same v2 manifest. Fronted by skillroutine-eval matrix mode, which resolves the matrix spec, eval context, and script paths — invoke the skill, not the workflow, unless debugging.

- **args**: `{parallelizeScript, skill, skillArgs?, contextDoc?, models?, efforts?, argVariants?, replicas?, baseCommit, skillMd, contextFiles?, qualityContext?, resultsDir?}`. `parallelizeScript`, `skill`, `baseCommit`, `skillMd` are required strings; `resultsDir` defaults to `sessions/skillroutine-eval/<skill>-<baseCommit[0:6]>`.
- **What it does**: Fan-out calls `workflow({scriptPath: parallelizeScript}, ...)` — the nested parallelize run shares this workflow's concurrency cap and budget. Zero surviving cells short-circuits (`manifest: null, eval: null`). Manifest is a low-effort mechanical agent that copies each cell's artifact out of its ephemeral worktree (fallback: `git show <cell branch>:<path>`), writes `resultsDir/manifest.json` in the skillroutine-eval manifest contract, and validates it with jq; unrecoverable runs land in `missing[]`. Eval is one agent invoking the skillroutine-eval skill on the manifest, unattended.
- **Returns**: `{parallelize: {consolidation, disqualified, failed}, manifest, eval}` — a dead manifest agent returns `manifest: null` with an `error` noting artifacts may still sit in cell worktrees.

### Authoring conventions

- One file per workflow, filename = `meta.name` + `.js`, located at `skills/<fronting-skill>/workflows/`.
- Keep scripts pure orchestration: batch resolution, user-facing reporting, and review gates belong in the fronting skill, not the script.
- Structured results always: define a result schema per agent instead of parsing free text.
- Document each new workflow with a section in this file (args, what it does, returns).
