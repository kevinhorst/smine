**FACT-REPO-STACK-001** — Go 1.26 module `github.com/kevinhorst/smine`; `make audit` is the inner-loop gate: `audit-prelude` runs the three steps that write into the tree serially — `build-audit` (links `bin/acdsl`, `bin/rules` and `bin/verifiers/*` with `-buildvcs=false`, so a commit does not relink them and the Go test cache stays warm), `project -strip`, `generate` — then one `$(MAKE) -j` phase over `logged-<unit>` goals: mod verify, vet, `cross-build` (the Go build for Windows and the Go vet for Linux, the two forms CI proves), golden-check, workflow-gen-check, skills-check, `acdsl check` (verdicts cached per checkout under `bin/acdsl-cache/`, scope per registry entry: `files`, `tree` default, `none`), `acdsl fixtures`, Go tests without race, and the Rust crates whose files changed on the branch — `rules audit-crates` derives the base like a review (`BASE=<ref>` bracket, else the upstream fork point, else the merge-base with main), an agentwt change also runs heartbeat (path dependency), an empty or unresolvable change set runs both, `SCOPE=all` forces both; CI and `make audit-linux` pass `SCOPE=all`. Go tests are scoped by Go's own test cache (runtime file reads included), so the first run in a fresh worktree executes every package. Rust builds stay per checkout in `cmd/<crate>/target`: a target dir shared across worktrees reuses another worktree's test binaries, whose compile-time `CARGO_MANIFEST_DIR` then points the tests at that worktree's files. `make audit-linux` runs CI's two Linux jobs (`make audit SCOPE=all`, then `make test`, both always, either failing fails) in a container built from `cmd/tests/linux/Dockerfile` with the latest stable Rust as CI installs it, as an unprivileged user like CI's runner, on a one-commit snapshot copy of the checkout mounted read-only — on demand, outside both audits, Docker daemon required; the local toolchain can lag CI's, so a clippy lint new in the latest stable shows only there; Windows test runs stay with CI's `test-windows` job; `make audit-full` (the same prelude, then the gates, race tests, the changed Rust crates and the model queries, then the acdsl smoke — `cmd/acdsl/smoke_test.go` behind the `acdslsmoke` build tag, `make test-acdsl-smoke` — alone, since it projects, stages and strips real tracked files) is the release gate. Each unit's output goes to `bin/test-logs/<unit>.log`, the console gets one PASS/FAIL line per unit plus a failed unit's whole log; callers never add `-j`. golangci-lint keeps its cache and start-up lock per checkout (`bin/golangci-cache`, `bin/golangci-tmp`) and lints only the packages of Go files changed against the merge-base with `main`, so worktrees lint concurrently and runs in one checkout queue.
