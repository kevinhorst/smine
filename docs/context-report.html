Context report

The session context report shows what the hooks injected into one session, per mechanism and per agent (root and every subagent), in chars and tokens.

Open it from the config server's Sessions → context list: the peek sessions of every registered repo, or the picked one, by week and local day. Only each week's newest day is open, a day's label toggles it, and each day shows three rows until "show all".

A row's title opens the report at /sessions-report/<id>; the row also links its peek view when a peek dashboard is configured, and its mined record when one exists. Download .md gives the report as markdown. Injecting hooks: Context system.

What is measured

Every injection, as the transcript recorded it reaching the model.

SourceCounted

ReadsSuccessful Read results of injected context-required files and language guides.
Projection blocksACDSL projection blocks in transcripts recorded while the hook still wrote them.
OtherContext-pack reads and Agent prompts.
Codex sessionsTheir AGENTS.md instructions turn, environment context and plugin list.
Not countedAllow-only hook output (a JSON decision without additionalContext): it never reaches the model.

A projection block counts only where acdsl project -file writes it: the file's first line, after a #! line or closed front matter, in that file's Read result. Claude sessions since the read-context change carry none; their rules show under Hook injections as acdsl-context. A marker anywhere else is a quote, not an injection: a file or transcript mentioning one, Grep, Bash or MCP output, or a Read starting below the file's head.

Sections

Each section but Plan-time rules is one table, one row per subject: a file, a skill, a projected file, a prompt, a hook and its subject. A row sums over the selected agents and shows the agents (the name for one, N agents for several), the injection or read count, and one size figure. Rows sort by tokens, then chars, heaviest first; a table wider than its section scrolls sideways inside it.

Guides read in full

A guide counts as read in full when an agent's Reads cover line 1 to the guide's end as the session saw it: the highest line any agent's Read of that path returned. The read gate makes every agent read a governed guide to its end, so no file on disk is consulted and closed sessions are judged like live ones.

A row reads read in full, lines a–b of N for a single partial reader, or k of n agents in full.

Selecting agents

The agent query parameter selects whose context the page shows; the chips and agent-table rows link to its values.

ValueShows
(absent)Every agent.
rootThe root agent.
type:<agent type>Every agent of that type.
id:<agent id>One agent.

The server computes every section, count, size badge, the total row, pending notice, touched files and markdown download for the selection only. The agent table still lists every agent, dimming those outside it. Filter-bar links keep the selection, and the selection keeps the filter. Peek's tiles (runtime, cost, tokens, cache) stay session-wide.

Invoked skills belong to the root and show only when it is selected: one row per peek skill_invoked event, with start and end from peek's per-skill runs. An open run shows no end; a session peek no longer serves shows none.

Token counting

Codex text is counted offline with OpenAI's o200k_base tokenizer: exact for the gpt-5 and o-series families, ≈ for others. Claude text goes to Anthropic's count-tokens endpoint, which needs an API key, so counting is off by default.

Enable it (macOS only):

  1. Create a scoped key

    In the Anthropic Console, create a dedicated workspace with the lowest monthly spend limit and an API key scoped to it. count_tokens is free; the limit caps a leaked key.

  2. Store it in the OS credential store

    macOS: the login keychain; the value is prompted, never typed on the command line.

    security add-generic-password -s com.smine.configserver -a anthropic-api-key -w

    Windows: a generic Credential Manager entry.

    cmdkey /generic:com.smine.configserver/anthropic-api-key /user:anthropic-api-key /pass:<key>
  3. Turn counting on

    A dev server reads the same setting from its dev home's install record.

    smine-rules settings set routines.count_tokens keychain

Background counting

The page never waits for the API: it renders with the cached counts and shows the rest as pending. One background run per session counts them: identical texts once, 30 API calls per minute, 200 injections per run, two minutes at most.

The page polls /sessions-report/{id}/counting and reloads once when the run has finished; anything still pending is counted on the next manual reload. Texts over the size limit show as skipped.

Skill body tokens

make skill-render counts each skill's deployed body (SKILL.md without frontmatter) into the tokens field of the newest changelog row in <leaf>.cue when the keychain item is readable; otherwise it prints one warning line and leaves the row untouched. The invoked-skills table looks the count up by version: the one the skill-context header recorded, else the one deployed now, marked ≈.

CLI

Prints a session's record as JSON (smine-batch's sessions[].context), tokens uncounted.

make context-record ARGS="~/.claude/projects/<munged-cwd>/<session>.jsonl [ctx-dir]"
