Config server

A Go and htmx web app on :6001 that edits ~/.claude/settings.json and shows what the loop produces.

It reads the nightly's open change commits (claude-routines/smine-nightly-*-proposals branches, via agentwt unplaced) with run-report verdicts and task records, rejected and dropped refs (History tab), session records and skills. Applicability: one agentwt probe per refresh, cached behind a ref fingerprint. Feedback-loop diagram: overview; setup: Install.

Access token

Every request needs the access token as HTTP Basic password; only its SHA-256 digest is stored, in ~/.claude/configserver/credential.

Live sessions

GET /sessions-context lists peek's sessions of every registered repo, or the picked one, by ISO week (newest open) and local day (each week's newest open, others closed until their label is clicked), three rows per day until "show all". Empty while peek is disabled; retries every 15 s while peek does not answer. A row's title opens /sessions-report/<id>.

Archive

ActionEffect
Archive: POST /sessions-archivegit mv of a scope's folder, committing only the moved paths: records stay tracked. A folder git does not track (archived before these actions used git) is renamed plainly.
Unarchive: POST /sessions-archive/{name}/unarchive

Actions are refused unless the sessions dir is a git checkout; the page redirects only on success.

Context page and repo registry

The server also manages multi-repo worktrees, scheduled routines (launchd, Task Scheduler on Windows) and per-skill analytics. Its command-line flags: Development § Config server flags.

The Context page (/context) browses the docs and sets each entry's and rule's reach, per detail page or in bulk (reach row's bulk reach picker, set reach button). It builds a registered repo's context overlay, picked by registry name; Write to Repo writes it into the repository. Engine: Go deploy engine in internal/contextdocs (Install § Deployment).

The repo registry

~/.claude/smine/repos.json lists the registered repos. env holds the repo's skill values: SKILL_<SKILL>_<KEY> keys only, none empty. Each skill page's Environment section writes its own keys.

{
  "repos": [
    {
      "name": "smine",
      "path": "/absolute/path/to/smine",
      "env": { "SKILL_FIMPLEMENT_CHECK": "make audit" }
    }
  ]
}

Session liveness

Live session data comes from peek, which the server spawns and talks to over MCP. Peek down: the session column degrades, pages still render. Details: Peek.

Config page

Five tabs: Smine, Hooks, Permissions, Claude, Codex. /config lands on Smine.

/config/smine configures the hooks and the heartbeat daemon. A tile grid, three per row, has one tile per catalog component with settings: title, settings count, on/off, overridden count. Below: one component's settings, the tile ?component= names or else the first (active tile highlighted).

Permissions tab

/config/permissions shows the live permission lists of ~/.claude/settings.json under the top-level headings Allow, Ask and Deny. Each rule head is a collapsed section (first open); its rows toggle a rule into settings.disabled.json or remove it. Each list has an add form.

Above sits the Claude settings' Sync, Force sync and Persist overrides widget (overridden count at its right end), to write live rules back into the repo fragment. Counts and state badges sit at the right edge of their heading or head row.

Telemetry and usage analytics

Spend history lives in the usage store ~/.claude/smine/usage, filled by the routine smine-budget: an hourly launchd job (minute 7) that starts no agent. Each run:

#Step
1Mirrors every Claude Code transcript and its subagent files into usage/archive/. The archive only grows: only a larger source replaces a copy, never an equal, truncated or emptied one. History outlives Claude Code's transcript cleanup and peek's watch window.
2Captures each session's peek usage (root, skill runs, subagents) and session-report context breakdown.
3Runs ccusage (v20.0.20 or newer, on PATH) over that archive and Codex's store: the independent price check.

Peek and ccusage, the two cost sources, are each an installation component. One off: smine-budget skips that side, the page offers the other alone. Both off, or Routines off (nothing else fills the store): no Usage page, no Overview cost tile.

/usage reads only that store: one source, or both with agreement verdicts, plus an error card per source that failed in the last run. Cost-per-day chart: dollars or plan percent (tokens weighted per model against the one measured Team Premium 5-hour window) for the plan picked on the page, Team Premium or Max 20x.

Skill and tool efficacy still come from Claude Code's native OpenTelemetry (OTel) events, received by peek (Peek § Claude Code telemetry).

Routines

Routines wrap claude -p in launchd jobs; the routine binary runs every job and holds its locks and timeout. Operations manual: Routines.

To add one, copy routines/_templates/ into routines/<name>/, rename the plist to the label and edit the marked spots, or use /skillroutine-create. First real routine: routines/smine-nightly/.

Trash

Nothing smine removes or overwrites is lost: previous bytes go to ~/.claude/smine/trash/<stamp>/<original path>, each event appends a line to ~/.claude/smine/journal.jsonl (Trash).

/trash opens from the trash icon at the Overview's bottom right; no nav tab. It lists stashes newest first, each file with size and a Restore button, then the newest 200 journal lines.
