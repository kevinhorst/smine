Skill model

A skill is a program, not a markdown file: <leaf>.cue is a typed model with its own logic and validation, and SKILL.md is rendered from it.

The model carries what prose cannot: typed routing and pipeline edges that must agree across skills, entry roles with their registers, a permission manifest, interface bindings for every program the skill calls, a smoke declaration, title states, the changelog. Every load validates all of it, so a wrong role, a route to nowhere, an undeclared tool or a version without its changelog row does not render. The file sits in the leaf dir, named after it (skills/quality/railroad-review/railroad-review.cue); payloads/<entry-id>.md holds template bodies. SKILL.md renders from both at deploy, never committed; only repo-scoped values wait for invocation (Interfaces and environment). Layout: Skills directory.

Never

A SKILL.md, title.json, enforce.json, smoke.json, answer.md or env.json in a skill dir fails make skills-check.

Formal clauses

pred: boolean expression over atoms (risk_map and dispatch_prepared, mode = nightly). post: atoms the entry makes true when it fires. internal/skillmodel.Derive turns them into the semantic model without judgment.

Entry roleBecomes
rule with predinvariant

An entry without clauses is uncovered, not an error. make model-analyze SKILL=<name> runs the solver on the derived model. Clauses must always parse; on the strict tier every atom must also resolve against the skill's atoms or skills/vocabulary.cue (ACDSL-SKILL-013).

An atom's source marks an input the world sets: | -separated parts, each one of these.

PartMeaning
arg: <row>[ => <member>]Args row, leading dashes stripped; => <member> forces an enum member.
sessionFact of the invocation's session.
environmentFact of the machine or repo.

Shared atoms (skills/vocabulary.cue) take none; anything else fails the load. Format-3 and shared atoms live only while a stop, rule or quality pred, a route section pred or a query reads them; a step's pred keeps nothing alive. Format-2 locals live with any pred.

Interfaces and environment

A skill never names a smine program: every tool, command or path it calls is a variable bound to one catalog interface. One skill thus runs on a full install, a partial one, or a colleague's machine with their own tools.

ScopeValuesFilled
installProvider programs.At deploy.
repoBuild, check, test, acdsl program, plans archive: per repository.At invocation, from the session's environment.

The catalog

skills/interfaces.cue holds interfaces and providers, loaded with every skill like vocabulary.cue. An interface is one capability a skill calls.

FieldRequiredMeaning
id, versionyesCapability, contract version; a binding names <id>@<version> (plan-sections@1).
kindyescommand (whole command lines, run bare), program (binary the skill appends args to), path (location) or skill (a deployed leaf name the skill hands off to, read in a Skill(…) grant and the hand-off statement).
scopeyesinstall or repo; every command record is repo.
summaryyesOne line, what it does; quoted in an unset repo-scoped variable's abort sentence.
exampleon a repo-scoped recordFitting value (go build ./..., bin/acdsl): skill-page placeholder, abort-sentence example.
invocationyes{cwd, args, stdin, timeout}; a program's args open with its subcommand word (plan-sections <plan file>); timeout a Go duration or none.
resultyes{exit, stdout}; exit maps codes to meanings, with "0" and "other".
validateyes{resolves: true} for command and program, {exists: "dir" | "file"} for path, {} for skill (the value is one leaf name, nothing to locate).

A changed exit code, argument shape or output schema is a new version, never an edit in place.

Values

Deploy fills each variable from the first set source:

  1. The deploy process's SKILL_<SKILL>_<KEY> environment variable.
  2. The install record's SKILL_<SKILL>_<KEY> row (skills.variables, config server skill page).
  3. Repo-scoped interfaces: the global default (skills.defaults, keyed by interface id, Environment tab's global defaults card).
  4. The provider of the bound version: its PROVIDER_<ID> environment variable, its PROVIDER_<ID> row, then its catalog program if its component is in the render's set. A nil set, the canonical deploy, counts every component installed.
  5. Unset.

A provider row moves all of a program's capabilities at once; a SKILL_ row pins one.

Repo-scoped placeholders

For the Claude home a repo-scoped variable is never resolved, so never unset, at deploy (source invocation); it skips nothing there. Its reference renders as a harness placeholder reading SKILL_<SKILL>_<KEY> from the session's environment at invocation. The entry whose statement or payload reads it, else each reading item, becomes one fenced block the harness runs before sending the skill content:

```!
awk 'BEGIN { if (ENVIRON["SKILL_FIMPLEMENT_CHECK"] == "") { print "SKILL_FIMPLEMENT_CHECK: not set - <summary>, e.g. go vet ./... - <hint>"; exit 2 }; printf "%s", "\052\052SKILL-FIMPLEMENT-COMMIT-002\052\052 after \140" ENVIRON["SKILL_FIMPLEMENT_CHECK"] "\140 is green \342\200\224 one Bash call per line" }'
```
RuleDetail
No shell expansionThe harness checks the line against permission rules first, refusing shell expansion ($NAME, ${…}, $(…), backtick). So awk reads values via ENVIRON; no $ in the line.
EscapingOne single-quoted program; every text byte outside letters, digits, space and ,.:/_=+@~- is a three-digit octal escape awk decodes (backticks, quotes, braces, dollars, backslashes, brackets, line breaks, multi-byte runes). Abort message cut to the same characters.
Required unsetPrints SKILL_FIMPLEMENT_CHECK: not set - … with the record's summary and example, exits 2: invocation aborted; the harness forgives only exit 1 of search commands. Required guards first.
Optional unsetExits 0 silently; its entry or item vanishes whole.
Hint"set it for this repo on the skill page, or export it" in a deploy; "export it in your shell" in the bundle.
Install-scoped in the blockFilled value, escaped like text; no $SKILL_ reference survives, so the bundle scan needs no allowance.
Bash(awk *)Appended to allowed-tools when the skill declares a deferred variable; also in the gate template. The gate's awk fence admits the program: no redirect, pipe, system, getline.
env.jsonBeside SKILL.md with the Skill environment component: schema 1, skill, version, one entry per repo-scoped variable a rendered block reads (name, interface id, required, scope, summary, example). The skillenv hook exports each value (repo value, else skill default, else global default); refuses a typed /<leaf> or Skill call with an unset required value before the body expands (Install § Per-repo values). The gate fills grants from the same sidecars.
Without the hookShell exports reach the placeholder alike.

Z3 analysis

Because the model is typed, its rules can be questioned: a format-2 skill is a controlled-English rulebook (MUST, NEVER, If ⇒ STOP, VERIFY), and modeled, z3 answers whether rules contradict, whether an entry is unreachable, and "if a and b hold, can c?"

What the analysis layer is

An optional per-skill analysis tier (one <leaf>.cue field): authoring contract plus compile-time test suite. No runtime effect: deploy strips clause lines; the executing agent never sees them.

TierOpt-inWhat happens
AnnotationsdefaultAny skill's clause lines are parsed, syntax-checked, rendered (graph view, diagrams), never resolved against a vocabulary: intent documented like interface types, cheap, visible, unenforced.
Modeltier: "strict"Checked semantic model: atoms resolve, kinds pair legally, skillmodel check runs the z3 battery, queries/ is the test suite; make audit-full fails the release gate on an error finding or verdict mismatch. solve, query refuse annotation-only skills.
When to opt in

Interacting state: counters, modes, obligatory stops gating real actions, fan-out/join arithmetic, as in the railroad-review dispatcher. Linear prose protocols gain nothing.

Model

In memory, never committed, derived 100% mechanically from the clauses.

Clause sourceBecomes

No translation layer, review pass or committed semantic-model artifact: a pure function of <leaf>.cue plus skills/vocabulary.cue, structurally drift-free. Each invariant and transition keeps its entry id, so solver answers point at <leaf>.cue and SKILL.md entries.

Query

A JSON file in the skill's queries/: one question, frozen to re-ask forever.

FieldMeaning
assumeGiven ("suppose the run is nightly").
checkTested ("…can the gate pause?").
expectPassing answer: sat (a scenario where all holds together) or unsat (the rules forbid it).
Tip

"If a and b, c cannot be" is exactly: assume a and b, check c, expect unsat.

Reading the answers

AnswerMeans
satPossible. solve prints a witness a human can check (scenario: asks_user=false, mode=nightly, lanes_returned=4, …). Whole-model consistency wants sat: no contradiction.
unsat + core: …Impossible. The core, a proof sketch, lists clashing invariants and transitions by entry id, transitions first; premises (your assumptions, vocabulary exclusivity axioms) stay out.
unknownz3 hit its 10-second per-check timeout. No verdict; solve and query exit 2.

Can the review ask the user?

make model-query SKILL=railroad-review EXPR='not asks_user'
verdict: unsat
core: SKILL-RAILROADREVIEW-EXEC-002

EXEC-002 is the invariant not asks_user: no state with the review asking is reachable.

Note

Cores are minimal: of several rule chains forbidding one thing, the core shows one.

The battery

skillmodel check <skill dir> (make model-check SKILL=<name>) runs it on the derived model, one line per finding, then a summary:

<skill dir>: <severity> <check>: <message>
Check (run order)SeverityA finding means
validateerrorUnparsable clause, unresolved atom, illegal kind pairing, consumed bool atom without producer or source, or exclusivity member not a declared bool atom.
consistencyerrorInvariants and exclusivity axioms contradict; names the clashing invariants.
guardwarningGuard never holds under the invariants: entry dead.
redundant-guardwarningA pred conjunct follows from invariants and sibling conjuncts ("guard always holds" for a one-conjunct pred).
haltwarningA stop's guard holds in every allowed state: stops every run at its start.
preservationwarningFiring from a state satisfying invariants and guard can break an invariant once post atoms turn true.
reachwarningEntry or stop never fires within the complete bound. Or "unreachable under atom = member": reachable otherwise, guard feasible there.
completionwarningNo transition of the last phase with transitions fires within the complete bound: every run halts or stalls early.
RuleDetail
SeverityOnly errors fail check (exit 1); warnings exit 0. A validate error, or an inconsistent model after consistency, stops the battery. Later checks skip entries guard found dead.
TierAnnotation: validate only, no z3. Model: all eight, z3 on PATH or check exits 2. unknown on consistency exits 2, on a warning check yields an "undecided" warning.
BudgetOne z3 process per check family (consistency; guard, redundant-guard, halt, preservation; reach, completion); each obligation a check-sat-assuming selector, 10-second timeout.

Complete bound

Posts grant only bool atoms; int and enum atoms never change in a run. So a run changes state at most min(P, G) times, plus one step to fire the target.

complete bound = min(P, G) + 1
G = the number of granted bool atoms
P = the number of transitions granting at least one

An unsat reach verdict at that bound is therefore a proof, not a sample. P and G count only the cone of influence: atoms an effective guard, effective invariant or the question (assumes, check) mentions, closed over exclusivity groups. Unread atoms, such as observation atoms, get no step copies and don't inflate it.

smt and solve default to it; an explicit lower --bound or query bound runs, warning its unsat is no proof.

Route anchors

Anchors are solver semantics, not just drawing.

AnchorEffect
replaces: <items>While the route pred holds, replaced entries can't fire (guard pred and not <route pred>) and replaced rules' invariants are suspended (not <route pred> => <invariant>); the route runs instead.
phase windowRoute transitions fire only in the anchor's phases. replaces: lowest to highest replaced-entry phase. between: <after>..<before>: <after>'s phase to <before>'s; start, end and context-section sides unbounded. Entries within a section stay unordered.

Ad hoc queries

skillmodel query --expr '<expr>' <skill dir> (make model-query SKILL=<name> EXPR='<expr>'): does the model imply the expression? The solver asserts effective invariants, exclusivity axioms and not <expr>, no soft clauses.

VerdictMeans
unsatHolds; the core names the proving invariants.
satCounterexample: scenario: atom=value, ….

Validity, unlike a committed static query file's satisfiability (assume + check, sat = possible). Exit 0 on either verdict, 2 on error or unknown.

Dead-entry check

solve --reach unsat: no run ever fires the entry, because

  • its guard contradicts the rules;
  • nothing grants an atom its pred needs;
  • an obligatory stop blocks the way there;
  • a replaces route takes its place whenever it could fire.

At the default complete bound that is a proof (DEAD — unreachable within the complete bound); a lower --bound warns and prints only unreachable within bound <n>. A query file commits such a question with reach (an entry id) and optional bound in place of check. The battery's reach check already covers every entry and stop.

Inputs and refs

Closed producer/consumer system: an atom guarding flow is granted by a step's post or declared an input by its source (grammar under Atom). skillmodel check enforces producer-or-input on the model tier; the graph view shows inputs as invocation tiles in a column left of the structure.

Refs point into vocabulary (defs, payloads) or own-section wiring, never cross-section control flow: sequencing belongs to the condition system. A route may ref the entries its anchor clause names.
