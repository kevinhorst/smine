Skills directory

skills/ is the source of truth for every skill; the skills sync renders it one way into the home dirs.

The Go skills sync (internal/skills, via configserver -sync-skills) deploys each skill flat to ~/.claude/skills/<leaf> and ~/.codex/skills/. Model file: Skill model.

Skill structure

Layout

The scanner skillgraph.Discover reads this tree; the leaf dir name is the skill's identity.

skills/
├── vocabulary.cue      plain files at the root: ignored by sync (vocabulary.cue is the shared atom registry)
├── <leaf>/             first-level dir holding <leaf>.cue: a skill
│   └── <leaf>.cue
└── <group>/            first-level dir without one: a group directory
    └── <leaf>/         subdir holding <leaf>.cue: a skill
        └── <leaf>.cue
Warning

A dir still holding skill.cue fails the scan.

Workflows

Workflow scripts drive Claude Code's Workflow tool: deterministic multi-agent orchestration. Plain JavaScript, not run under Node: a sandboxed harness interpreter without filesystem, network or Node API access. Scripts are pure control flow; their subagents do all real work.

Invoking a workflow

Bundled with its fronting skill at skills/<group>/<leaf>/workflows/<name>.js, invoked by path, resolved against the skill's base dir (holding its SKILL.md, stated at skill load).

Workflow({scriptPath: '<skill base dir>/workflows/<name>.js', args: ...})
RuleDetail
Why bundledTravels with the skill on sync; independent of the working directory.
No name mode{name: ...} deliberately unused: resolves only scripts under .claude/workflows/, which this repo does not maintain.
BackgroundRun ID at once; progress in /workflows, result as a task notification.
argsVerbatim as a global: real JSON values, not stringified.
Entry pointThe skill, not the workflow, unless debugging (smine-mine, investigate, railroad-review).

Runtime model

The only orchestration primitives inside a script:

PrimitiveDoes
agent(prompt, opts)Spawns a subagent, awaits its result. opts.schema (JSON Schema) forces structured output, validated and retried at the tool-call layer, returned parsed. null if skipped or terminally dead.
parallel(thunks)Concurrent behind a barrier (waits for all); failed thunks → null.
pipeline(items, ...stages)Per-item stage chains, no inter-stage barrier; default for multi-stage fan-out.
phase(title), log(msg)Progress grouping, UI narration.
workflow(nameOrRef, args)Another workflow inline as a sub-step (saved name or {scriptPath}), sharing the parent's concurrency cap, agent counter, token budget. One nesting level: a child cannot call workflow().
budget{total, spent(), remaining()}: the turn's token target from a user "+500k"-style directive; hard ceiling, agent() throws once spent. Enables budget-scaled fleets, while (budget.total && budget.remaining() > N) loops. budget.total is null without a target: always guard on it, or the loop runs to the agent cap.
agent() optionEffect
model, effortPer call; effort low–max.
isolation: 'worktree'Fresh git worktree; expensive, only for parallel file mutation.
agentTypeCustom subagent from the Agent-tool registry.
label, phaseProgress UI.
ConstraintDetail
Concurrency≤ min(16, cores−2) agents at once, excess queued; lifetime cap 1000 per workflow.
DeterminismDate.now(), Math.random(), argless new Date() throw (would break resume).
No user inputA workflow cannot pause for it, hence every workflow here is skill-fronted.
meta blockEvery script opens with a pure-literal export const meta = {name, description, phases}.
ResumeRe-invoking with resumeFromRunId replays the unchanged agent() prefix from cache, re-running edited or new calls only. Same script and args: full cache hit.

Dynamic shapes

"Dynamic workflow" is Anthropic's product name for the whole feature; the official docs apply it to every script, static or not. Useful axis (investigation 2026-07-24, sessions/investigations/baseline-dynamic-workflows.md): dynamic in shape iff the agent() call set is not a pure function of script text plus args.

TierAgent setIn this repo
T0 staticFixed at parse time.Unoccupied; former analyze is now output-gated smine-mine (T2).
T1 arg-shapedFrom args, before the first agent runs.railroad-review.
T2 output-gatedSpawning depends on agent outputs.investigate (Stage-B verifier shard count from the deduped claim count), fdesign refute (tie-break agent only on split verdicts). Skill evaluation: headless roots via go run ./cmd/skilleval, no workflow.
T3 iterative, convergentLoop predicate reads outputs or budget: loop-until-dry, budget loops, threshold-gated widening, adversarial multi-verifier voting.Supported by the tool contract, unoccupied. railroad-review's approve-loop is the dispatcher-driven station protocol, one invocation per round (human gates cannot live in a workflow); the workflow stays T1.

Determinism is orthogonal: T3 too stays resume-replayable; dynamic means data-dependent, never nondeterministic. No repo script uses budget or a while loop yet; railroad-review uses pipeline() for its per-direction lane→dedup→refute chain.

investigate

Fans out N independent investigations of one open analysis or data question, re-verifies each load-bearing claim against its actual primary source, merges into one baseline with a refuted-hypotheses register. /investigate fronts it, resolving question, inputs, fan-out width. Script: skills/verdict/investigate/workflows/investigate.js.

ArgRequiredMeaning
questionyesString.
inputsyesString of fetchable sources: paths, live or archived URLs, prod-query targets.
artifactsDiryesAbsolute session-scratchpad path outside every worktree, for investigator artifacts; never the repo.
priorArtifactnoExisting analysis, as investigation #1.
investigatorsnoDefault 3, cap 8.

Throws on missing question or inputs, missing or non-absolute artifactsDir, investigators over the cap.

StageDoes
A, Fan-outinvestigators general-purpose agents, one parallel() barrier. Each reads inputs first, ranks hypotheses, names the primary source of every load-bearing claim; never reads siblings (anti-anchoring).
B, Re-verify (v1.2)Dedups claims across runs, crediting every raising run; shards of ≤8, one medium-effort verifier each, in parallel. Each fetches every claim's actual primary artifact, never a prior run's summary; rules holds | refuted | needs-measurement, watching the full funnel. Shard verdicts union into one verification register.
C, MergeOne high-effort agent writes the baseline: fact-vs-hypothesis labels, refuted-hypotheses register, credited net-new findings, discrimination plan.
Measurement gateneeds-measurement claims return as open_measurements with concrete prod queries. Subagents cannot pause for you: the fronting skill surfaces them, re-invokes with resumeFromRunId once your results return as binding facts.

Returns {investigators, failed, verification, baseline}: surviving investigator outputs, failed run ids, verification register, merged baseline, each per its agent's result schema. No survivor: verification: null, baseline: null.

Warning

Fixed artifact filenames, <artifactsDir>/inv-N.md: a second run on the same artifactsDir overwrites the previous reports. Move them before re-invoking.

railroad-review

One station-protocol round, one stage file per spawn under skills/quality/railroad-review/workflows/: review fanned out to n lanes per direction in isolated worktrees; same-defect claims collapsed by lightweight groupers (per direction, then across); every claim second-confirmed by a capped pool of fresh refuters and verifiers; one station review, single review.json handoff; round worktrees and branches cleaned up.

/railroad-review fronts it; multi-agent only (solo removed in v7.0). The dispatcher (the session running the skill) owns everything around the per-round invocations:

  • Scope: committed range, or snapshot commit over uncommitted and untracked work; snapshotting.
  • Base: empty-diff guard, autonomous base derivation (never a prompt), diff-base confirmation.
  • Risk-map tiering, direction selection.
  • Station-protocol loop and every human gate: rejection ledger, fix loop (fix-apply with per-package commits via package-commit, applied ledger state, probe replay and fix check, fixed ledger state), two consecutive clean rounds.

Authoring conventions

  • One file per workflow stage, meta.name + .js, at skills/<group>/<leaf>/workflows/; several spawns, one file each (railroad-review).
  • Scripts stay pure orchestration; batch resolution, user-facing reporting, review gates belong in the fronting skill.
  • Structured results: a result schema per agent, never free-text parsing.
  • Document each new workflow here: args, what it does, returns.
