Heartbeat

A background daemon per Claude profile tracking each session's state: running, waiting, blocked, idle, ended or died.

You and orchestrator agents read session state here, not from transcripts. Landing flow: Merge strategy; stateless gate rules: Permission System.

Address

When heartbeat is down

Sessions keep working, with a hook error notice per event; no heart attack runs.

A restart rebuilds only sessions with a ~/.claude/sessions/ file and a transcript at <claude home>/projects/*/<id>.jsonl. Hook-only sessions stay unknown until their next hook, then show since_restart; old ledger denials do not re-block them.

Heart attack

The heart attack is heartbeat's own kill: heartbeat alone, no orchestrator or subscription, is allowed to end a session's agent automatically. Its one application today is the model policy: it stops any subagent on a forbidden model, spawned without a model, or whose transcript model lacks the named one.

AspectRule
SparedRoot session; subagents with an allowed, matching named model.
#disable hbIgnored (heartbeat spells it); mutes every other /hook answer.
Policyheartbeat.forbidden_subagent_models: globs over model ids and Agent-call aliases; default empty (forbids nothing), set per install. Live key, via the config watch.
SightingsA denied Agent call with forbidden model input; a transcript whose first assistant line shows a forbidden model (read on tool hooks until known).
StopThen every PreToolUse, PostToolUse, PostToolUseFailure of the subagent gets continue: false, reason as stopReason and systemMessage; it ends at its next tool hook. An inherited forbidden model gets one tool call before it is read.
See itsmine-heartbeat status --session <id> --format json: each subagent's model.
Model aliasesRequested token proves nothing: haiku runs the session model on this account; hence stopping missing or mismatched models.
Limits

Long tool call: the subagent stops when it returns. Started before a heartbeat restart: unregistered, never stopped. Hook answered past Claude Code's 1 s timeout: no stop; the next carries it.

Git state

serve --repos <claude home>/smine/repos.json enables git state. The file is read at start and watched: a repo registered on the Repos page is scanned and watched at once, a removed one leaves the rows, no restart. A file not written yet (no repo registered) is an empty registry; a malformed one degrades the git sensor and keeps the running set.

Runtime enforcement

Skills declare enforcement in the enforce block of <leaf>.cue; deploy renders enforce.json beside the deployed SKILL.md only if the install holds both gate and heartbeat components. No file: no enforced run, no gate rule.

Patterns carry install-scoped $SKILL_… variables, filled with this install's program, regex-quoted (^smine-rules base ). An unset variable drops its anchor plus the checks and judgments naming it. The model check refuses repo-scoped variables in anchors (Skillcue § Interfaces and environment).

Stateless gate rules: the tool-policy gate (Permissions). Heartbeat enforces anchors and checks in every session, reporting failed checks and judgment points to the session's one watcher, its bound /runtime agent.

/heartbeat-demo scenario:<name> shows each layer acting, one scenario per rule, check and ladder step. Only tests cover the rootDenied gate rule and the runtime stop move (cmd/toolpolicy/enforce_test.go, cmd/heartbeat/tests/scenarios/runtime.rs).

Moves

Each finding (check_failed, judgment) unlocks one move, once, while its run is open: send or stop, ledger-claimed (synced) before going live.

MoveEffect
runtime send <finding>

Renders the finding's template (the check's recovery or the judgment's send from enforce.json; placeholders {finding}, {skill}, {version}, {check}, {reason}, {evidence}). The act agent names finding and move, never text.

Reaches the raising agent (root or subagent) at its first chance: PostToolUse additionalContext on its next successful tool call. A root, usually waiting, gets it as Stop block reason or as UserPromptSubmit additionalContext on its next prompt.

At most once: lost if Claude Code drops the answer past its 1 s timeout; void if pending at run end.

runtime stop <finding>Arms (session, agent): that agent's tool hooks get continue: false until the root's next UserPromptSubmit (root) or its SubagentStop (subagent). Text heartbeat.runtime_stop_reason (kill: heartbeat.kill_reason), carried twice in every stop answer, as stopReason and systemMessage.

Verdict chain per hook answer: heart attack → member guard → runtime (subscriber guard, the hook's check decision incl. a killed session, armed stop, hand-over).

Read it

Fails open

Heartbeat checks lapse on HTTP hook failures (non-blocking in Claude Code), answers past the 1 s hook timeout, runs opened before a daemon restart (runs and findings are memory-only), --agent sessions and #disable hb sessions. Gate rules hold while the deployed enforce.json exists (gate and heartbeat installed); on an unparseable one the gate fails closed and heartbeat opens no run. SubagentStop runs no stop check.

Members

Attended sessions run /join fleet: T1 once, /done when work is committed and finished. Titles: … - T1-MA[WIP], [READY] after a committing turn, then [DONE]; /close leaves the fleet, ending at [CLOSED]. Outside a fleet, /done lands the session's own branch on its landing target; one based on the default branch lands nothing.

Orchestrator

  1. Start it

    From a session worktree of the repo:

    /fleet fleet: T1 target: <branch> [playbook: feature|design] [master: <plan file>] [collisions: all]
  2. Subscribe

    Subscribes as … - T1-O[WIP], never a member; switches its worktree to the run's merge branch (fleets[].merge_branch).

  3. Land members

    Judges collisions, fast-forwards delivered members onto the merge branch (git merge --ff-only), journals every act; never checks out the target. Members behind the merge branch are asked to restack and /done again; delivered worker branches behind it the orchestrator restacks on a work branch. Never a merge commit.

  4. Sync the target

    Once integrated, syncs the target via /done in its landing turn: restack if it moved, then an ancestry-checked fast-forward (smine-agentwt forward). A target checked out elsewhere moves in that worktree, refused only while it has uncommitted changes to tracked files (queue: sync blocked until you commit). A target that is no landing target answers no-target; the orchestrator stops.

  5. Finish

    Removes worker branches, runs unsubscribe --finish (the run dissolves). /close in its session removes the merge branch. Landing on main stays yours.

Worker cells

Each worker starts as a background command: a claude -p cell in .claude/worktrees/<name> on claude/<name>.

smine-routine worker -base <merge branch> -name <name> -skill <leaf> -args <text>

The launcher commits leftovers, removes the worktree, prints one JSON result line (status done, failed or stopped); its exit wakes the orchestrator. A cell is a root session, so its subagents work in its own worktree; a subagent's subagents were fenced to the orchestrator's.

-keep-stopped keeps a stopped cell's worktree; -resume <session id> continues it there with -args as next prompt, how the feature playbook hands a stopped implementer its refined plan.

Merge strategy

A session's branch lands on the branch it started from, by replay and fast-forward, never by a merge commit. Heartbeat grants the turns (Landing); this section is who lands what, when.

RuleWhat it means
Land on the baseA session lands on its base, the branch it started from, if that is a local branch neither agent-owned nor default; a fleet member on its fleet's merge branch; any other branch on none. This is its heartbeat row's target.
No targetStarted from main or with an unknown base: nothing restacks or lands it; you pick its commits.
Staging targetUnset unless heartbeat.staging_target names one (develop below). Takes finished feature branches; you release it to main.
ReplayNever a merge commit: a branch behind its target is restacked onto the target's tip, then the target fast-forwards.
One at a timeHeartbeat grants one landing turn per repository and target.
mainNo agent session pushes or moves it. Two operator tools write it: the routine runner lands the nightly's session records (with auto-merge on, also a judge-accepted night's ready changes), never pushing; the Proposals page's Pick uses smine-agentwt pick.
Your git actsUnbound: no hook, no deny. The next landing handles any ref state you produce.

Landing a session

/done in a session in no fleet. You type it; an agent's own call is admitted only after /join or inside /fleet.

  1. Clean tree

    Uncommitted work is committed first.

  2. Accept

    smine-heartbeat done resolves the landing target and requests its turn: accepted <target> granted or queued <n>. Queued: the session ends its turn; heartbeat's message when the turn frees resumes it at step 3. No target: no-target <base>, title to DONE, nothing lands.

  3. Create

    A missing staging target is created from main's tip after the grant; heartbeat grants its turn before it exists.

  4. Catch up

    If main holds commits the staging target lacks, the staging target's unreleased commits replay onto main's tip and it moves; the old tip stays as claude-restack/<slug>-<short>-orig.

  5. Placed check

    smine-agentwt unplaced --onto <target> <branch> lists the commits the target lacks; none: the turn ends abandoned.

  6. Restack

    They replay onto the target's tip on a work branch (conflicts resolved by both sides' intent, audit run), unless the target's tip is already in the branch. The checked-out branch keeps its name; its old series becomes the -orig archive, removed through the safety-gated remove once adoption is green (kept if the removal is skipped). Any other branch stays on its work branch for the caller to adopt, with no archive.

  7. Fast-forward

    smine-agentwt forward --onto <target> <tip> moves the target after checking the tip holds the target's tip.

  8. End
    smine-heartbeat land --end landed
  9. Close

    /done --close then runs /close, removing the session's worktree and branch; the Desktop session stays open.

CaseRule
Every exit ends the turnStopped restack, unmoved target, nothing to land: abandoned. Fix the cause, type /done again; --close then closes nothing.
Checked-out targetChecked out in another worktree (your main checkout on the feature branch): fast-forwarded there, index and files following. Refused while that worktree has uncommitted changes to tracked files: commit there, type /done again.
Restack never asksDecides every conflict, contradicting changes included, naming each call in its report. Where nothing decides between two intents, it keeps the target's behavior and fits the replayed commit to it.
Stopped restackOnly a red audit or an unattributable file stops it: branch untouched, work branch kept; a rerun onto the same tip resumes.
Fleet member/done --close delivers and closes nothing: the orchestrator lands the branch first.
Feature branch/done branch: <local branch> lands a branch without a live session, always on the staging target; refused for the staging target itself, main and agent branches. Turn via smine-heartbeat land --target <staging target>; no rename.
PlansOnly a feature-branch landing archives plans. Between restack and fast-forward, each feature folder under plans/ it brings goes through /plan-archive on the tip: wip plan dirs are copied to the plans archive as done-<tip hash>, committed there, then removed by a commit landing with the feature. The staging target and main never hold a wip plan. A session's own /done leaves plans on the feature branch for later sessions. A stopped archive ends the turn abandoned; the next landing replaces the archived copy.
Other target/done takes no target; only /restack onto: <branch> moves a session, making that branch its base.
ArchivesRestack removes its own -orig archive after adoption. /close removes the session's claude-restack/<slug>-… branches (slug from the session branch) through the same safety-gated remove, keeping and reporting any whose commits nothing else holds.
Stuck turnsmine-heartbeat land --release <target>, in the repository, ends the holder's turn. A turn also ends when its session ends or dies; never by clock or prompt.

Landing a fleet

Members land on the fleet's merge branch; only the orchestrator moves it.

StepRule
DeliverA member runs /done (delivered <token>); a spawned worker counts once stopped.
At the tipA member whose branch holds the merge branch's tip lands by git merge --ff-only.
BehindAn attended member is asked once to restack onto the merge branch and /done again; the orchestrator never writes into a member's branch.
Stopped workerNo session: the orchestrator restacks its branch on a work branch, fast-forwards to it, deletes the work branch.
SyncOnce every worker landed, the orchestrator calls /done. The merge branch was cut from the fleet's target, its landing target, so /done lands it in that target's turn, staging create and catch-up included. A target that is no landing target: no-target, the fleet stops.

Skill model merges

A custom git merge driver merges two branches' version bumps of one skill model file.

RuleDetail
Binding.gitattributes binds every <leaf>.cue with skills/*/*.cue merge=skillcue and skills/*/*/*.cue merge=skillcue; root files interfaces.cue and vocabulary.cue keep git's text merge. Git calls the driver in merge, cherry-pick and merge-tree.
Driversmine-rules merge-skillcue %O %A %B %P %X %Y, registered as merge.skillcue.driver by the installer (git config --global) and the routine cell image (git config --system).
OrderBoth sides' new changelog rows stay. The side with the later committer time (from git's %X/%Y conflict labels) goes on top, a tie to the incoming side; row dates decide when a label resolves to no commit. Rows renumber upward from the base version, each by its bump kind; the frontmatter version follows the top row.
FallbackAny other conflict in the file: git's text merge with markers, exit 1, one stderr line naming the reason.
Probes without a worktreeAgentwt runs merge-tree with GIT_ATTR_SOURCE=<onto tip>, so the binding applies in a container cell with no .gitattributes on disk.
Placement checks stay driver-freeAgentwt's in-memory gix merges (status, unplaced, the fleet order, heartbeat's git edge) only ask whether a change is already on a candidate, which no driver changes. Agentwt drops every merge.<name> config section on opening the repository: gix turns a driver's conflict exit into a hard error.
