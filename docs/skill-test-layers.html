Skill tests

Three layers test a skill: smoke, eval and A/B, each answering one question.

The skill (producer) declares its own smoke and eval; the runners (consumers) read the declarations and name no skill. Chain position: Skill map.

Note

The workflow layer has no behaviour test: make workflow-gen-check (an audit unit) proves block freshness and the shape rules of every committed stage file. Only smoke and eval runs exercise a script's logic.

Smoke layer

Checks the skill runs end to end under its own constraints, on a dummy input, in minutes. Never a quality judgement.

Declaration

The smoke block in <leaf>.cue: a skip reason or a run. Every skill declares it; make skills-check fails without. The runner loads the model and resolves the defaults in memory; no file is rendered.

FieldMeaningDefault
skipWhy the skill has no smoke run.
invokeText after /<leaf>. {token} becomes the run's TOKEN label, so no label is checked in.
modenightly or interactive (Modes).nightly
fixturetree and patch under the skill's smoke/ dir.
expectAnchors, or a check command.
envRepo-scoped values the run sets, by env key: every required repo-scoped variable of the skill, model-checked.
limitsBudget and timeout.3 USD, 15 minutes
modelRun model.sonnet
effortRun effort.low

smoke/ is never deployed.

Runner

The consumer, skilleval, reads only the declaration and names no skill. It runs on the eval's machinery: provision, headless arm, heartbeat capture, cleanup.

CommandRuns
make skill-smoke SKILL=<leaf> TOKEN=<label>skilleval smoke
make skill-smoke-verdict SKILL=<leaf> SESSION=<id>skilleval smoke-verdict

Deployed copy first

A smoke runs only the deployed skill, so the runner first checks it came from the checkout's source. Deploy writes source <sha256> into ~/.claude/skills/<leaf>/.smine-deployed: the hash of every skill-dir file but eval/ and smoke/, projection blocks stripped. The runner hashes the checkout's skill dir alike (skills.IsDeployedCurrent); a different or missing stamp refuses with exit 3.

Order

Change, deploy, smoke. The check hashes sources only, reading no install or repo values, so a smoke runs from any checkout.

No machine values

A nightly smoke never sees the machine's repo-scoped values. Before the session starts, the runner:

  • unsets every inherited SKILL_* variable but the arm's SKILL_CONTEXT_INDEX;
  • sets the smoke block's env values as SKILL_<SKILL>_<KEY>;
  • sets SMINE_SKILLENV_OFF: the skillenv hook exports nothing, neither the install record's defaults nor a registry row.

Stores

A nightly session never touches the live proposal and backlog stores; the plans archive is fenced (no read, no write, whatever grant the skill holds). The store root is store/ in the throwaway worktree (SMINE_STORE_ROOT), as make rules ARGS="store-root" and store-check answer there.

Verdict

Mechanical; a failure names its first cause.

VerdictWhenPasses when
Terminalexpect.check, or no expectationWall time under limits.minutes, cost under limits.usd; a session exists, exit status 0, terminal reason completed, result success, no error flag; the check, run in the worktree after the session, exits 0.
Heartbeatexpect.anchorsTerminal rules; the session's run row of the skill exists, not killed, no failed check, every expected anchor; coverage minimums. A missing row's cause tells heartbeat not answering from no enforced run of the skill opening.
Interactivesmoke-verdictNo stream, so no limits or session rules: the run row exists and has ended, then the heartbeat row rules and coverage minimums.

Coverage

Heartbeat smokes only; zero for a terminal-verdict smoke. Two ratios, each over its total in the deployed enforce.json: declared anchors hit, declared checks passed at least once. expect.minAnchors (hits over all declared anchors) and expect.minChecks are minimum ratios; unset means 0.

Record and cache

Each run writes one record per skill and deployed version to ~/.cache/claude-routine/artifacts/smoke/<leaf>/<version>/, never under ~/.claude/smine, never committed; the previous same-version record stays beside it as <version>.<n>. A run executes in smoke/.staging/ and moves into place after cleanup.

Eval layer

Measures how good one skill configuration's output is on a real task, with time, tokens and cost.

Declaration

eval/definition.json in the skill dir, schema skills/skillroutine/skillroutine-eval/reference/definition.schema.json (4.0, gate ACDSL-JSON-005).

PartDeclares
InvocationFree text, the skill's args as data, the args a run may set:.
EnvironmentRegistry repo, range or checkout commit, overlay.
LimitsBudgets and prerequisites.
Configurationmodel (default opus), effort (default high), replicas (default 1).
Check and referenceOptional check argv and reference commit.
ScoringThe scoring contract, below.

Running

/skillroutine-eval <skill> [replicas: <n>] token: <label> [golden: produce|test] [set: <name>=<value>]
  1. Init freezes the run

    go run ./cmd/skilleval init composes the prompt and freezes the run from the definition: prerequisites, the golden kind's file, token label, runs × armUsd against the window.

  2. The skill runs the replicas

    Provisions, launches the replicas, spawns the adherence judge (plus golden judges on a test run).

  3. Cleanup and report

    Cleans up, folds, reports. The skill interprets nothing in the definition.

Scoring

Exactly one scoring contract per skill.

ContractKeysResult
Goldenfindings, goldens, scoringThe golden path, unchanged: candidates, golden judge, review score and minutes.
Scorerscorer.commandAn argv run in each run's worktree after the check; stdout is one JSON object {"metrics": {"<name>": <number>}}, names [a-z][a-z0-9_]*. Values land in result.json scores and in eval.json as score_<name>. A failing scorer leaves scores absent, its cause in runs/<label>/scorer.log.

Every run also gets generic measures: mechanical verdict (smoke_pass), check_pass, wall and active time, output tokens, cost, permission denials, heartbeat check failures, adherence-judge step misses. Wall is the arm stream's own span summed per process, excluding a resumed run's session-limit pause; active time is peek's main-loop figure. The eval's notes give the definition's open args at the run prompt's values.

Output

Record dir evals/<skill>/<date>-<hash6>[-<n>]/: the hash is the checkout commit, -<n> a same-day repeat.

Accounts

token: <label> names an OAuth token stored from the config server in ~/.config/claude-routine/tokens/<label>. Only the label travels; the arm process exports the value as CLAUDE_CODE_OAUTH_TOKEN. Init refuses an unknown or missing label, listing the stored ones. Reports name token <label>.

Limits

  • Headless has no plan mode: fdesign ends at the written plan.
  • Runs of one eval run in parallel inside one usage window.
  • A skill without a definition cannot be evaluated.

A/B layer

What one change did: the difference between two record sets of a lower layer.

/skillroutine-ab <skill> [layer: eval|smoke] variant: <descriptor> [replicas: <n>] token: <label>

Variant descriptor

Names exactly one factor against the definition's baseline. Two changes, none or an unknown factor is refused (ab-init exit 72).

DescriptorLayerHow it runs
model:<name>, effort:<level>evalSide by side: both sides in one run dir, equal replicas, shuffled blind labels.
no-<mcp server>evalSide by side. Void unless the baseline shows the server connected.
overlay:<repo-relative patch>evalSide by side; the variant applies the definition's overlay plus the patch.
version:<a>..<b>eval, smokeRuns nothing. Heartbeat and the gate read the one deployed copy, so versions compare sequentially: run at <a>, deploy, run at <b>, then A/B. The smoke layer's only descriptor, as its cache keeps one record per deployed version (exit 73 otherwise).

Side by side, the blind compare judge ranks the outputs against the definition's reference commit when one exists.

Output

Record dir evals/<skill>/ab-<date>-<hash6>/.

FileHolds
ab.jsonDescriptor, layer, both record sets with measures, and per-measure differences: means, standard deviations, n, Δ mean, Welch's t, df, significance at alpha 0.05.

Statistics come from go run ./cmd/evalstats -ab <ab.json>; fewer than two records per side gives df 0 and no significance.

Limits

An IDE comparison (no-goland) needs a definition whose invocation opts into the server: the descriptor varies the runner, never the invocation.
