Agentwt

One Rust binary that judges every worktree's integration state and merge order and writes one JSON document per repo.

It replaces cmd/worktrees/print_agent_worktrees_status.sh, cmd/worktrees/_lib/verdict.sh, the merge, cherry-pick, sync and remove scripts, and smine's Go status parser; the smine config server renders its output. Evidence for each choice: the fleet research notes in git history (docs/fleet-research.md).

Modules

inventory reads worktrunk, gitstate judges each branch with gix, sessions joins the session registries, order computes the conflict matrix and train, ops replaces the scripts.

gitstate: gix

Opens the main repo once; bare access suffices, no working copy.

AnswerHow
FROMThe branch reflog. A bare SHA origin resolves to the candidate branches containing it (an ancestor check per candidate); a routine chain resolves through the previous routine to its root. unknown only when nothing contains the SHA.
Ahead/behind vs FROMTwo rev-walks; worktrunk's numbers (vs the default branch) stay separate.
UnpickedPatch-id per commit = hash of its diff against its first parent (gix diff, whitespace-normalized); unpicked when it appears in no candidate's merge-base..candidate range. Replaces git cherry.
Applied verdictCherry-pick simulation: merge_trees(base = commit^, ours = FROM tip, theirs = commit); clean and result tree == FROM tree → applied. No probe worktree.
Merged-intoEach candidate's first-parent history searched for a merge commit whose non-first parent is the branch tip. Cheap; kept.
DroppedResolved and picked-resolved (range-diff interdiff, subject twins): no library equivalent; the order module answers the same question forward-looking.
Untracked filtergix status as the git status equivalent, excluding .idea/, .claude/, .claude-worktree, .DS_Store; the remove gate uses the same list.

order: matrix and train

#StageRule
1InputsDefault tip M, agent tips B1..Bn, plus a dirty snapshot per worktree (the working tree written as a tree object into a throwaway object store), so live edits count: the gap in clash.
2PrefilterTouched-path sets from merge_base(M, Bi)..Bi; disjoint pairs commute.
3Pairwisemerge_commits(Bi, Bj) with TreatAsUnresolved::git(), fail_on_conflict for the cheap probe, rename tracking on; store clean or the unresolved paths. Filter with is_unresolved; never count every entry (clash's defect).
4TrainT0 = M; per candidate order, merge_commits(T(k-1), Bk). Clean: write the merged tree and a synthetic commit into the throwaway store, continue. Conflict: record (k, paths), continue from T(k-1). Objects go to a temp object dir with the repo objects as alternate; nothing lands in .git/objects.
5OrderingConflict-graph components merge independently. Within one: greedy fewest-conflicts-with-remaining, brute force for components ≤ 6, verified with the train. Per branch: conflicts_with, train position, first blocking pair, residual conflicts.
6CostN=12 → ≤ 66 pair merges, in-process, sub-second.

ops: replacing the scripts

OpRule
mergegit merge --no-edit <branch> semantics into the main checkout's HEAD: refuse dirty, abort on conflict. gix has no porcelain merge with working-copy update: shell to git for this one command, or implement merge_commits + checkout. Never wt merge.
cherry-pickSame rule.
syncMerge base into the branch, never rebase.
removeOwn safety predicate (contained somewhere, clean tree under the untracked filter), then git worktree remove. Not wt remove: it refuses locked worktrees and uses default-target containment.
Destructive flags

--force and --delete-branch destroy work as named, so the Go callers archive first: the Repos page salvages a checked-out worktree before a forced removal and writes the branch diff before a deletion, both into one trash stamp, and refuses the removal if the archive fails.

Output contract

One JSON document per repo, rendered by the config server; nothing else parses git.

FieldHolds
repoThe repository.
checkoutbranch, dirty
rows[]worktree, branch, from, counts (vs FROM and vs default), verdicts, merged_into, contained_in[] (with a reason per candidate), unsafe_reasons[], session{}, order{conflicts_with[], train_position, blocking}

Three-state fields serialize as absent / null / value, mirroring worktrunk, so the UI keeps one rule.
