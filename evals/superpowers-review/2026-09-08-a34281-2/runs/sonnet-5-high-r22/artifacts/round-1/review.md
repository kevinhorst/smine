## Strengths

- **Registry read-through (`internal/repos/registry.go`)** is a clean, well-targeted fix for the documented last-writer-wins resurrection bug (FACT-REPO-ARCH-016): `Add`/`Remove` now re-read `repos.json` under the lock before applying their delta, `save` records the new file identity so a self-write never triggers a spurious reload, and `refreshIfChanged` does a cheap stat-based check before any full parse. Matches the `2026-08-30-repo-cache-reload` plan almost line-for-line, including the accepted "same-second same-size write" caveat, and ships the exact test matrix the plan calls for (`TestRegistryAddPreservesExternalEdit`, `TestRegistryDeleteStaysDeletedAcrossInstances`, etc.).
- **Status-cache fingerprinting** (`repos.Fingerprint`, `statusCache` entry + `handleRepoWorktreeStatus`) gives a genuinely deterministic invalidation rule (git refs + worktree list, ~20ms) instead of a TTL guess, and degrades correctly on fingerprint error (treated as "changed", never as "trust the cache"). The dead `handleRepoRemove` endpoint and route were actually deleted, not just deprecated.
- **`internal/acdsl/policy.go`'s use of the *base-ref* policy as authoritative, not the working-tree one**, is a real improvement over the plan's own pseudocode. The plan's `CheckPolicy` sketch checks `policy.Mode == Free` using the *working* policy before ever computing the boundary or diffing the surface — which would let an agent flip `mode` to `free` in the working copy and short-circuit before the surface-diff (which would otherwise have caught that exact tamper) ever runs. The shipped code instead resolves `base` first and re-reads the policy from that commit (`basePolicy`) before deciding anything, so a plain "set mode to free" edit is caught by `surfaceDelta` as intended. This should be pointed out as a deliberate, justified deviation worth folding back into the plan doc — it's better than what was approved, not a shortcut.
- **`internal/peek/peek.go`'s `SessionIndex`** (branch-keyed + cwd-keyed) is a correct, minimal fix for FACT-REPO-ARCH-017 (pool-recycled worktree dirs stealing another session's identity); `worktreeSessions` in `repos.go` prefers branch match with cwd as fallback exactly as documented.
- `bootstrapEnv`/`handleWelcomeBootstrap`/`cmd/bootstrap/run.sh`: the extra-prompt value is passed as an env var into a script that only ever hands it to `claude -p` as a single quoted argv element (never re-parsed, never `eval`'d) — no shell-injection path despite accepting fairly permissive characters (only quotes/newlines are rejected). Token values are handled correctly (read from file, never logged, `TokenName` in the UI is a label not the secret).
- Translation catalog, template diffs, and the large batch of `changelog.json`/`SKILL.md` edits are additive and low-risk; no unescaped-HTML template patterns introduced.

## Issues

### Critical (Must Fix)

- **`internal/acdsl/policy.go`: the self-management gate is fully bypassable by setting `base_ref` to the current branch's own name.** `policyBase` (policy.go:195) picks the merge-base candidate from `policy.BaseRef` — read from the working-tree `acdsl/policy.json`, i.e. attacker/agent-controlled on their own branch — and then derives `isBoundary` as `branch != baseName` where `baseName` is that same candidate string. If `base_ref` is set to the literal name of the branch currently checked out, `GitMergeBase(HEAD, ownBranch)` trivially returns HEAD's own commit, `GitBranch() == baseName`, `isBoundary` comes back `false`, and `CheckPolicy` takes the `if !isBoundary { return nil, nil }` early-out ("on the base branch — humans change the surface here") — for **every** kind of violation (surface tamper, protected-scope rule add/remove, unsanctioned overlay entry), regardless of `mode`.
  - **Verified by reproduction**: built a throwaway git repo with the existing test harness (`newPolicyRepo`, committed `mode: gated` base policy with `editable_scopes: ["GOLANG"]`), added a protected-scope `ACDSL-PLAN-999` rule on the `work` branch. `CheckPolicy` with the untampered policy correctly flags it. Setting `policy.BaseRef = "work"` (the checked-out branch's own name) makes `CheckPolicy` return zero diagnostics for the identical tree — full bypass, in an isolated `git worktree add --detach` copy of the actual reviewed commit (not the contaminated `arm-wt` tree).
  - This defeats the feature's entire purpose (TLDR: "the loosy-goosy-rules failure mode is structurally closed" via git-topology privilege boundary, D4: "agent worktrees on `claude/*` branches can never self-escalate"). It is not an exotic attack: it requires one plain-text edit to `acdsl/policy.json` (no commit needed — `LoadPolicy`/`policyBase` read the working file straight off disk) and no special git state.
  - It is also plausible as an honest mistake, not just an attack: `policyBase`'s candidate-resolution comment and the README's "base_ref override for shallow clones" guidance (D10 / `acdsl/README.md` Modes section) never warn against pointing `base_ref` at the agent's own branch, and `TestCheckPolicyUnresolvableBase` is the only test that exercises a non-default `BaseRef` — it only covers the "ref doesn't resolve" hard-error path, never the "ref resolves to my own branch" self-reference path. This gap is untested in both directions (plan and implementation).
  - The `acdsl-policy-guard.sh` PreToolUse hook (advisory, fail-open by design per the plan) blocks `Write`/`Edit`/`NotebookEdit` on `acdsl/policy.json` in gated/strict mode, but not `Bash`-driven writes (`printf ... > acdsl/policy.json`), so the hook is not even a meaningful speed bump against a deliberate bypass — and per the plan's own D2, the binary check is supposed to be the *authoritative* layer specifically because the hook isn't.
  - **Fix direction:** `isBoundary` must not be derived from a value that itself lives on the surface being gated. Either (a) resolve the base independently of any working-tree-supplied `base_ref` (hardcode the trunk-candidate list, or source `base_ref` only from the *base-ref-committed* policy the way `basePolicy` already does for `Mode`/`EditableScopes`/etc.), or (b) after resolving `base`, independently verify `base` is a proper ancestor of HEAD *and* that the resolved ref name is not the currently checked-out branch, treating a self-referential resolution as the same "unresolvable base" hard error as D10 rather than as "on the base branch, skip." Whichever fix lands needs a regression test for exactly this case (`base_ref` == own branch name).

### Important (Should Fix)

- **Presentation-profile parsing is duplicated verbatim** between `cmd/bootstrap/run.sh` (lines ~54–66) and `routines/smine-nightly/run.sh` (lines ~25–37): the same `sed`-based extraction of `language:`/`audience:`/`dev-mode:` from `presentation-profile.md`, the same `dev_mode` env-override-then-profile-then-casual-forces-off chain, and (in `run.sh`) the same `skill_overlay` copy-into-`.claude/settings.local.json` block appears twice more (once in `cmd/bootstrap/run.sh`, once in `routines/smine-nightly/run.sh`). Both routines already source shared helpers from `routines/_lib/` (`platform.sh`, `skill.sh`) — this is exactly the kind of cross-cutting logic that belongs there instead of copy-pasted, per `ACTION-REVIEW-QUALITY-005` (no unnecessary duplication). A future change to the profile file format (e.g. an added field) now needs to be kept in sync by hand in two places with no test tying them together.
- **`routines/smine-nightly/run.sh`'s orchestrate-stage `additionalDirectories` reconciliation (lines ~296–303) mutates the user's global `~/.claude/settings.json` unconditionally whenever `orchestrate=1` and both files exist**, with no guard for `jq` being absent (the script only checks `jq`/`shellcheck` presence in `cmd/bootstrap/run.sh`, not here) and no lock against a concurrent writer of the same file (the config server's own repo-add/remove handlers write this same settings file via a different code path). A `jq: command not found` here leaves a stray empty `.tmp` file (harmless) but a legitimate concurrent write from the config server while this block runs risks a lost update (last-writer-wins on `mv`) — worth at minimum flagging as an accepted risk in the plan the way the `Registry.save` cross-process race was.

### Minor (Nice to Have)

- **`internal/server/presentation.go`'s `saveProfileSelection`** resolves the German onboarding template via a bare relative literal, `filepath.Join("settings", "claude_code", "presentation-profile.de.md")`, instead of going through any of the repo-root resolution the rest of the config server uses for equivalent paths (e.g. `claudeFragment` in `cmd/configserver/main.go` is at least a named, overridable flag with the same relative-path assumption). It works today because the launchd plist always sets `WorkingDirectory` to the repo root, but it's untested — neither `presentation_test.go` nor `profilesettings_test.go` exercises the casual+German first-activation seeding path — and a `go test ./internal/server/...` run from any other cwd would silently skip the seed (falls back to empty body, no error). Worth at least a unit test with a temp cwd, or threading the repo root through like the settings fragment.
- `cmd/hooks/skill-invoke-gate.sh`'s Bash-target detection for the "don't read context files directly" rule only recognizes a literal two-word `cat <file>` command (line 62–72) — `head`, `less`, `sed -n`, `python -c`, etc. all pass through unexamined. Given the hook already documents itself as fail-open/advisory (consistent with the ACDSL policy hook's posture), this is a known-narrow net rather than a broken one, but it's worth confirming that's an accepted gap rather than an oversight, since the comment doesn't call it out the way the ACDSL guard's doc explicitly does ("this hook is fast feedback... the authoritative layer is the binary check" has no analogue here — nothing else re-checks this constraint later).

The shipped `acdsl/policy.json` on the reviewed commit matches D11 exactly (`mode: free`, `dist_mode: gated`, language scopes) — I initially misread this as a deviation because `arm-wt`'s dirtied working copy shows a different, gated-for-smine version; that dirt is harness noise, not part of `a342811b`, and I've discarded that finding after checking `git show a342811b:acdsl/policy.json`.
- `2026-08-30-repo-cache-reload`: matches the plan's three phases exactly (registry read-through, fingerprint-based status-cache invalidation, dead-endpoint removal), including the "optimistic delete stays exactly as-is" constraint and the specific test names called out in the plan's Tests table.
- Other plans under `plans/v1-2-1/` (bootstrap-profile-improvements, smine-profile-settings, language-style-setting, repos-routines-improvements, peek-multiple-profiles, plan-format-viewer-fixes, railroad-review-observability, session-context-report) were used as requirements context but not diffed against their implementations line-by-line at the same depth as the two plans above — see Method note.

## Recommendations

- Add the missing regression test for the `base_ref` self-reference case before anything else in this range ships to a `gated`/`strict` target — this is the one finding that undermines the stated purpose of a whole feature area.
- Factor the presentation-profile parsing (and the skill-overlay copy) out of `cmd/bootstrap/run.sh` and `routines/smine-nightly/run.sh` into `routines/_lib/`, matching the existing shared-helper pattern in this same diff.
- Fold the base-authoritative `CheckPolicy` design decision back into the `2026-08-26-acdsl-policy-modes` plan's Decisions table (or a Changelog row) so the plan and the shipped code agree on why the working-tree policy's `Mode` is never trusted directly — right now that reasoning lives only in a code comment.

## Assessment

**Ready to merge?** With fixes.

**Reasoning:** The bulk of this release (repo registry/cache reload, peek session attribution, bootstrap/profile UI, routine scheduling) is solid, well-tested, and matches its plans closely, with a full green build/vet/test suite on a clean checkout. But the ACDSL self-management policy engine — the mechanism the release explicitly bills as closing the "agent edits its own rules" failure mode — has a confirmed, low-effort, fully-reproducible bypass (`base_ref` set to the agent's own branch name) that silently defeats the gate for every mode and every violation class; that alone should block distributing `dist_mode: gated` to targets until it's fixed and covered by a test.
