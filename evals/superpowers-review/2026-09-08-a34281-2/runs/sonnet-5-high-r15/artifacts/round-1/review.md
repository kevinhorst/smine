## Issues

### Critical (Must Fix)

#### 1. `acdsl/policy.json`'s `base_ref` lets an agent branch declare itself the policy base, disabling the entire self-management gate
- **File:** `internal/acdsl/policy.go:195-219` (`policyBase`), exploited via `CheckPolicy` at `internal/acdsl/policy.go:329-346`; root cause shared with `internal/acdsl/git.go:36-42` (`GitBranch`) and `:69-75` (`GitMergeBase`).
- **What's wrong:** `policyBase` resolves the trust boundary using `policy.BaseRef` read from the *working tree's own, potentially agent-committed* `acdsl/policy.json` — not from any already-verified base. If an agent (on a `gated`/`strict` repo) commits a change to `acdsl/policy.json` setting `"base_ref"` to the **name of its own current branch**, then:
  - `GitMergeBase(ctx, root, "<own-branch>")` returns `HEAD` (merge-base of a branch with itself is its own tip).
  - `GitBranch(ctx, root)` returns the same branch name.
  - `policyBase` returns `isBoundary = (branch != baseName)` → `false`, because `branch == baseName`.
  - `CheckPolicy` sees `!isBoundary` and returns `nil, nil` at line 344-346 ("on the base branch — humans change the surface here") *before ever computing `surfaceDelta`* — so the very edit to `policy.json` that performed the attack is never flagged, and no rule-delta check runs at all.
  - This defeats every stated design goal (D4 in the acdsl-policy-modes plan: "agent worktrees on `claude/*` branches can never self-escalate") and the plan's own D2 rationale ("a registry verifier is self-defeating... reliable only in the binary") — the binary itself is defeatable the same way.
- **Mitigating factor:** `cmd/hooks/acdsl-policy-guard.sh` denies `Write`/`Edit`/`NotebookEdit` on `acdsl/policy.json` once mode is non-free, which blocks this via the Claude Code tool surface — but the hook is explicitly documented as advisory/fail-open, and it does not gate arbitrary `Bash` writes (`sed`, heredoc, `cat >`) to the file, which remain fully available. The plan's own stated design (`CheckPolicy` "not bypassable via data files... reliable only in the binary") is not met.
- **Why it matters:** this is the exact security boundary the whole feature exists to enforce (uncontrolled rule/verifier tampering by an agent). A one-line policy.json edit fully disables it, including for the surface-freeze check that is supposed to be the last line of defense.
- **How to fix:** never derive the trust boundary from the *working tree's* policy — resolve `base` once from the fixed candidate chain (or an operator-configured `base_ref` that itself lives only on the base branch, read via `git show <resolved-base>:acdsl/policy.json`, never from disk), and compare `HEAD` against that independently-resolved commit, not against a caller-suppliable ref string. At minimum, refuse any `base_ref` value that resolves to the current `HEAD`'s own branch.

## Recommendations

- Given the acdsl policy engine is the newest and most security-sensitive piece of this release, it would benefit from a short adversarial pass (a second reviewer or a dedicated red-team plan) specifically targeting the base-resolution logic before this ships to any repo that actually sets `mode: gated`/`strict` — smine itself stays `free`, so the blast radius today is limited to future target repos, but the bug is real and structural.
- The plan-traceability gaps (#2, #3, #4) are all in areas the repo's own doctrine treats as load-bearing (RULE-PLAN-049, ACTION-REVIEW-SPEC-005). A quick reconciliation pass — either back-filling the missing plan docs/Changelog rows or confirming these were deliberately out-of-band — would close them cheaply.
- Given the size of this diff, a second review pass focused specifically on the ~50 SKILL.md/template files I did not line-diff (the jargon-rule additions across smine-context/-memory/-routines/-skills, the i18n catalog completeness, and the Windows-specific install/scheduler code) is warranted before calling this release fully audited.

## Assessment

**Ready to merge?** With fixes.

**Reasoning:** The bulk of this release (registry/cache concurrency rewrite, worktree squash-detection, UI/routines changes, bootstrap wrapper) is careful, well-tested, plan-faithful work with a clean build and green test suite. But the new ACDSL self-management policy gate — this release's one genuinely security-relevant addition — has a structural bypass that lets an agent branch disable it entirely via a single `policy.json` edit, which must be fixed before any repo actually turns on `gated`/`strict` mode (smine's own default stays `free`, so nothing in this repo is exposed today, but the feature does not yet do what it says on the tin). The plan-traceability gaps are lower stakes but should be reconciled before sign-off.
