## Strengths

- **`internal/repos/registry.go` read-through rework** matches its plan (`2026-08-30-repo-cache-reload`) almost to the line: `readRegistrySnapshot` stats before reading (so a racing write is caught on the *next* stat, never silently missed), `Add`/`Remove` re-read fresh state under the write lock before applying their delta (closes the stale-in-memory-slice resurrection bug), and `save` re-stats after writing to record its own identity so a self-write never triggers a spurious reload. All four planned regression tests (`TestRegistryRefreshOnExternalEdit`, `TestRegistryAddPreservesExternalEdit`, `TestRegistryRemoveAfterExternalEdit`, `TestRefreshKeepsLastGoodStateOnParseError`) are present and pass, plus race-clean.
- **Status-cache fingerprint invalidation** (`Fingerprint`, `statusCache.Store` gaining a fingerprint param, `handleRepoWorktreeStatus` comparing it) is a clean, cheap (`git for-each-ref` + `git worktree list`, no `git status`) mechanism that gives a one-sentence answer to "when does this reload" — implemented exactly as planned, with the accepted-staleness tradeoff (dirty/untracked counts) explicitly documented rather than silently swallowed.
- **ACDSL self-management policy (`internal/acdsl/policy.go`)** is the standout piece of this release. It correctly closes a hole its own plan's pseudocode didn't spell out: the plan's example `CheckPolicy` reads `mode` from the *working-copy* policy, which would let an agent branch flip `mode: "free"` in its own working tree and bypass gating entirely. The shipped code adds `basePolicy()` to re-resolve the authoritative mode from the merge-base commit before gating, and this exact scenario is covered by `TestCheckPolicyBaseModeSurvivesWorkingWeakening`. That's a genuine, tested improvement over the plan, not a drive-by embellishment — it directly serves the plan's own stated goal (D4: "agent worktrees can never self-escalate").
- Policy engine test coverage is thorough: strict/gated/free, task-contract exemption, verifier allowlist (explicit and base-registry-derived), overlay bypass closure, unresolvable-base hard failure, marker-reorder-counts-as-change — all present and matching the plan's test table.
- `Fingerprint`/`WorktreeCounts` reuse `shell.Run` consistently (no raw `exec.Command`), matching the repo's `ACDSL-GOLANG-EXEC-001` gate.
- `bootstrap.go`'s headless one-shot run is well-built: the multi-hour child gets its own `context.WithTimeout` (6h) independent of `shell.Run`'s 60s ceiling, exactly mirroring the documented `routinewrap` precedent; the token path and prompt are passed as separate `exec.Command` args / positional shell params rather than interpolated into a command string, so there's no injection surface despite the token and model coming from a config file.
- `install.sh` / `install_windows.go` per-install port persistence (`install.env`, `{{PEEK_CONTROL_PORT}}` template expansion in `sync_settings.sh`) is symmetric across the Unix and Windows install paths and consistently wired through to the one Go consumer (`internal/config/installenv.go`).
- The `claude-review/*` branch-namespace change for railroad-review fan-out lanes (moving them out of the `claude/*` prefix that the repos-UI worktree table and general-purpose `remove_agent_worktrees.sh` sweep watch) looks at first glance like a coverage gap, but it is an explicit, documented, user-approved tradeoff in `2026-08-26-railroad-review-observability` (D5/D6): cleanup is expected to rely solely on the round's own explicit `--delete-branch` calls. Not a finding — flagging here only because it's the kind of thing that reads as a regression out of context.
- `internal/peek/peek.go`'s `SessionIndex` (adding `ByBranch` alongside `ByCwd`) is a straightforward, well-targeted fix for the documented pool-worktree-recycling misattribution problem, and `routineSession`'s prefix-matching against both the group worktree and the `-cells` sibling correctly guards against false prefix matches by requiring the path separator after the prefix.
- `parseSchedule` → `scheduleInfo{Intervals, Supported, Unscheduled}` cleanly distinguishes "no schedule configured yet" from "scheduled via a launchd mechanism this tool doesn't understand" — a real usability fix, not just a refactor.

## Issues

### Critical (Must Fix)

None found. Build, vet, full test suite (including race), and the full shell test suite are all green on the actual reviewed commit.

### Important (Should Fix)

1. **`settings/claude_code/settings.json` — the `ask` permission entries for `acdsl/**` and `**/*.acdsl` were deleted, not replaced.** (`settings/claude_code/settings.json`, commit `5c11486`, part of "settings: presentation profile and settings.json updates".)
   - Before this change, any `Edit`/`Write` to an ACDSL rule/registry file required interactive confirmation, in this repo. After: `defaultMode: "acceptEdits"` applies to those paths with no confirmation and no `deny` entry added in its place. The new `acdsl-policy-guard.sh` hook provides no compensating protection here, because it is a no-op whenever `acdsl/policy.json`'s `mode` is `free` — and smine's own policy is deliberately `free` (D8: the `smine-apply` generation flow needs to write `registry.json`/rule files unattended). So the net effect in *this* repo is: friction removed, and the new gate doesn't apply.
   - This is not necessarily a bug — it may well be the deliberate fix for the `smine-apply` headless routine: if `acdsl/**` sat in `permissions.ask`, an unattended `claude -p` run (no TTY to answer a prompt) writing to `acdsl/registry.json` as its sanctioned, voted generation flow would have stalled or been denied. Removing the ask entries would unblock exactly that. But this reasoning appears nowhere — no plan, no commit message, no README line mentions it (the acdsl-policy-modes plan and the shipped `acdsl/README.md` "Modes" section only discuss adding a `deny` snippet to *targets*, never removing `smine`'s own `ask`).
   - **Please confirm which of these it is.** If it's the unattended-routine fix, it's worth a one-line comment/commit note so the next person doesn't "restore" it. If it wasn't deliberate, this quietly reopens exactly the failure mode ("rule sprawl", accidental ACDSL edits) that the whole policy-modes feature exists to close — in the one repo (smine itself) where the policy engine provides zero backstop.

2. **`internal/shell/shell.go`: `RunSync` duplicates `Run`'s entire body** (only the timeout constant and the error-message prefix differ — `Timeout`/`"Run:"` vs `SyncTimeout`/`"RunSync:"`). Roughly 20 lines duplicated verbatim, including the `WaitDelay` comment and the `platformArgv`/`HideWindow`/logging sequence. `internal/shell/shell.go:19-67`. Two sanctioned entry points into this package now diverge in behavior only by copy-paste, so a future fix to one (e.g., the `WaitDelay` grandchild-pipe workaround, or the log line shape) can silently miss the other. Straightforward fix: extract a private `run(ctx, dir, timeout, name, args...) (string, error)` and have both exported functions call it with their own timeout and message prefix.

### Minor (Nice to Have)

1. **`cmd/hooks/skill-invoke-gate.sh`'s post-invocation context-read denial is narrowly scoped and easy to step around by construction, not by malice.** It only inspects the `Read` tool and a literal two-token `cat <path>` `Bash` command; any Bash invocation containing a quote, `$`, backtick, parens, `;`, `|`, `<`/`>`, or `&` is skipped entirely (target stays empty, so nothing is denied) — including the extremely common `cat "path/with/no/spaces"` (quoted for habit, not need). `grep`, `head`, `sed -n`, `less`, or a second Read via a different path alias also aren't covered. The script's own comment frames this correctly as a "fast feedback" layer with no authoritative binary backing it (unlike the ACDSL policy gate, which is enforced in `bin/acdsl` itself) — so this is calibrated as Minor, not Important. Given this hook exists specifically to keep the railroad-review/superpowers-review golden-eval lane isolation clean, it's worth knowing the isolation is a nudge, not a wall, if that assumption is ever load-bearing for eval validity.
2. **`install.sh`/`install_windows.go`: the `lsof -tiTCP:<port> -sTCP:LISTEN | kill` pattern, now applied to two more ports (`PEEK_PORT`, `PEEK_CONTROL_PORT`), will silently no-op if `lsof` returns more than one PID line** (e.g., a dual-stack listener reported twice) — `kill "$pid"` with a multi-line `$pid` fails as a single malformed argument, swallowed by `|| true`, and the following `kill -0` wait-loop then also fails immediately and falls through as if the process were already gone. This is pre-existing behavior (the same pattern already existed for `$ADDR_PORT` before this change) that's now duplicated a third time rather than fixed — flagging only because three copies of the same latent multi-pid gap is worth a shared helper eventually, not because this diff introduced it.
3. Plan-vs-code is otherwise very tight; the one deviation worth naming for the record (not a problem) is documented above under Strengths: `CheckPolicy`'s `basePolicy()` re-resolution step isn't in the plan's Changes-section pseudocode, but it's exercised by a named regression test and is clearly in the spirit of D4 — treating it as a sanctioned improvement, not a gap between plan and delivery.

## Recommendations

- Add a one-line commit/README note on the `settings.json` `ask` removal (Important #1) so its intent survives the next person reading `git blame`.
- Fold `Run`/`RunSync` into one private implementation (Important #2) before a third timeout variant shows up.
- If eval-lane context isolation (Minor #1) is ever asserted as a hard guarantee somewhere (a plan, a doc, an eval methodology writeup), that assertion should be corrected to "best-effort" or the hook's Bash-command matching should be widened (e.g., strip a matched pair of quotes before falling back to the safe-skip).
