## Strengths

- **`internal/acdsl/policy.go`** (the ACDSL self-management mode engine, 394 new lines) is genuinely well built: the base-ref-authoritative design (a branch cannot weaken its own policy by editing/deleting the working `policy.json`) is correct and closes the obvious self-escalation hole, it's covered by 15 focused table-driven tests exercising free/gated/strict, task-contract exemption, verifier allowlist, overlay sanctioning, unresolvable base, and marker-line-changed detection, and the mode enum is a closed `switch` in `parsePolicy` that hard-errors on an unknown value rather than silently defaulting (good adherence to ACTION-IMPL-INTEG-005's spirit).
- **`internal/repos/registry.go`**'s `Add`/`Remove` now re-read `repos.json` from disk under the lock before mutating (`readRegistrySnapshot`), replacing the old load-once-then-write-whole-slice pattern. This is exactly the fix `FACT-REPO-ARCH-016` calls for (read-modify-write, not IPC coordination) and directly closes the "second configserver instance resurrects a deleted repo" bug.
- **`internal/server/statuscache.go`** + the `Fingerprint`/`refreshIfChanged` machinery in `repos.go` give the worktree-status cache a single, explainable invalidation rule (git fingerprint mismatch or `?refresh=1`), replacing three previously-disagreeing staleness mechanisms — matches the plan's target state precisely, including the deliberate choice to keep the optimistic-delete path and only drop the now-stale rows from the cache (`DropBranches`) rather than touch the removal flow.
- **`internal/peek/peek.go`**'s `SessionIndex` (ByBranch + ByCwd) and its use in `repos.go`'s `worktreeSessions` correctly implement the fix `FACT-REPO-ARCH-017` documents (attribute by branch identity first, cwd as a detached-HEAD fallback) — the pool-dir-recycling bug this closes is real and the fallback order is right.
- **Security posture on the new HTTP-triggered subprocess spawn** (`handleWelcomeBootstrap`, `internal/server/bootstrap.go`) is handled responsibly: `cmd/configserver/main.go` gates any non-loopback bind behind an explicit `-allow-remote` flag with a comment stating plainly that every endpoint is unauthenticated — the right call given the new endpoint can kick off a 6-hour, `acceptEdits`, real-token `claude -p` run.
- Test coverage on new/changed Go code is consistently present and follows the repo's table-driven/`_id`/`_shouldPass` conventions (`policy_test.go`, `dist_test.go` additions, `bootstrap_test.go`, `profilesettings_test.go`, `statuscache_test.go`, `registry_test.go`).
- The `Repo.Label` addition, the reserved-name guard (`default`/`archived`), and the non-git-folder `git init` on add (DR9) are all narrowly scoped, validated before any side effect fires (`repo.Validate()` before the op closure), and match their driving plan entries.

## Issues

### Critical (Must Fix)

None found.

### Important (Should Fix)

- **`routines/smine-nightly/run.sh:325-336` and `cmd/bootstrap/run.sh:163-171` — no rollback when the orchestrator agent fails or times out mid-merge on the real main checkout.** Both wrappers invoke `smine-orchestrate` against `$repo_root` — the actual main checkout, not a disposable pool worktree (the skill's own precondition is "cwd is the main checkout on branch `main`") — under a hard `--max-budget-usd` / wall-clock ceiling. The postcondition check only *detects* a dirty tree after the fact (`orchestrate left the checkout dirty`) and sets a non-zero exit; it never runs `git merge --abort` or resets to the pre-merge SHA. If the agent gets killed mid-merge-conflict-resolution (budget exhausted, `launchctl bootout` per `FACT-REPO-ARCH-012`, or a crash), the real checkout is left in a half-merged/conflicted state, and — since nothing resets it — the *next* nightly run starts from that same broken tree. The skill doc's own framing ("Any failure leaves the manual-merge world intact") doesn't hold for this failure mode: a clean *rejection* (no merge attempted) does leave the world intact, but a merge that starts and doesn't finish does not. Recommend either wrapping the merge itself in the wrapper (so it can `git merge --abort` on a nonzero orchestrate exit before reporting) or having the skill's own hard invariants include "on any failure inside step 2, `git merge --abort` before writing `.orchestrate-report`" as an explicit, wrapper-independent obligation.

### Minor (Nice to Have)

- **`cmd/hooks/acdsl-policy-guard.sh:43`** unconditionally denies *any* Write/Edit to `acdsl/registry.local.json` in gated mode, while the authoritative `overlayViolations` (`internal/acdsl/policy.go:531`) and the design doc both describe `local_overrides` as a sanctioned per-entry escape hatch in gated mode ("only entries listed in the policy's `local_overrides` are accepted"). This is faithfully implemented from the plan's own hook listing (`2026-08-26-acdsl-policy-modes-done-a7cd7bf/design/raw.md:450`), so it's not an implementer deviation — flagging it as a plan-level rough edge: an agent using the Write/Edit tool can never exercise a sanctioned local override in gated mode even when the override is pre-approved in `policy.json`, though it remains reachable via `Bash` (untouched by this `PreToolUse(Write|Edit|NotebookEdit)` matcher) and by `acdsl check` itself. Low severity because the authoritative gate is unaffected and a workaround exists; worth a follow-up note in the README's Modes section if the intent really is "the hook only blocks the tool-mediated path."
- **`internal/config/installenv.go:33`** (`installEnvValues`) doesn't strip inline trailing comments from a `KEY=value # comment` line — only a leading `#` on the whole line is recognized. Not exploitable (the file is machine-written by `install.sh`, not user-edited), but if a human ever hand-annotates `install.env`, the comment silently becomes part of the value.
- `plans/v1-2-1/2026-08-30-repo-cache-reload-wip-46c8d9e/design/change-repo-cache.md`'s own "Deferred findings" section flags that `handleReposDelete` never revokes the `additionalDirectories` grant `handleReposAdd` makes — correctly called out as explicitly out of scope for this change, not a finding against this diff, but worth tracking since it's now a slightly larger surface (casual installs always grant per this same diff's DR9/C6, so more repos accumulate ungranted-on-delete entries over time on non-dev machines).

## Recommendations

- The `$15`/`3600s` budget and timeout constants for the new `smine-orchestrate` invocations (both call sites) are asserted without a stated sizing rationale in the plan text (only the code snippet). Given the orchestrate step now runs `make audit` on merged main plus multiple sync scripts, worth a one-line note on how that number was picked, or a wider margin given a red audit forces a revert-and-reject path that itself costs turns.
- Given 9 plans landed in one range, a single top-level "what shipped in 1.2.1" note (even just linking the 9 plan TLDRs) would help a future reader reconstruct scope faster than re-deriving it from `plans/v1-2-1/*/design/*.md` Context sections, several of which cross-reference each other's drivers (e.g., the bootstrap-profile plan's DR7/DR10 vs. the non-dev-automation plan's DR3/DR7).
