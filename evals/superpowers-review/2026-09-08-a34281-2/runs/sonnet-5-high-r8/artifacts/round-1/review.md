## Strengths

- **`internal/repos/registry.go` (FACT-REPO-ARCH-016 fix):** `Add`/`Remove` now re-read `repos.json` under the write lock before applying their delta, closing the exact stale-in-memory-slice resurrection bug the fact describes. `refreshIfChanged` correctly stats-then-reads (avoiding a TOCTOU miss window worse than what's documented), degrades to "keep last good state + log" on a bad external edit instead of 500ing, and the change matches its plan (`2026-08-30-repo-cache-reload`) almost line-for-line, including the deliberately-accepted benign race noted in Hot items (two concurrent `refreshIfChanged` calls both reloading is harmless).
- **`internal/server/statuscache.go` fingerprint invalidation:** clean, small, and exactly matches its plan. `DropBranches` correctly keeps the pre-removal fingerprint on purpose (so the next plain load reconverges to scan truth) rather than the more "obvious" but wrong choice of refreshing it.
- **`internal/acdsl/policy.go` (self-management policy modes):** the implementation deliberately improves on its own plan's pseudocode. The plan's `CheckPolicy` sketch checks `policy.Mode == PolicyModeFree` on the *working-copy* policy before ever computing the base — which would let an agent trivially bypass strict/gated mode by editing `mode` to `"free"` in the working tree. The shipped code instead resolves the base ref first and re-reads the *base-ref* policy (`basePolicy`) as authoritative, so a branch can delete or edit its local `policy.json` and the base's real mode still gates (and the deletion itself shows up as a `surfaceDelta` finding). This is covered by a dedicated test, `TestCheckPolicyBaseModeSurvivesWorkingWeakening`. Good catch of a real self-referential bypass in the plan's own design, and it's the kind of Hot-item-worthy change that got the "present a full example in the plan" treatment the concept gate asks for, even though the final code diverged from that example.
- **`internal/peek/peek.go` `SessionIndex` (FACT-REPO-ARCH-017 fix):** matches the documented fact exactly — branch-identity attribution (`ByBranch`) preferred over cwd, cwd kept as the detached-HEAD fallback (`ByCwd`), `keepNewest` correctly uses per-iteration range variables (Go 1.22+ semantics, no loop-variable-capture bug).
- **`cmd/hooks/acdsl-policy-guard.sh`:** shipped verbatim against its plan's fully-specified script — bash-3.2-safe, fail-open on missing `jq`, correctly scoped to the repo actually carrying the policy file (walks up from `cwd`), doesn't try to parse Edit diffs (leaves that to the authoritative binary check, as the plan intends).
- **`routines/smine-nightly/run.sh` orchestrate stage:** reasonable safety layering for an autonomous merge-to-main pipeline — reject-never-half-merge, `make audit` re-check post-merge, dirty-tree and unmerged-branch are both hard postcondition failures the wrapper (not the LLM) checks, push is gated on `git remote get-url origin` succeeding. Consistent with its plan (`change-nondev-automation.md`).

### Important (Should Fix)

1. **`internal/acdsl/policy.go:329-335` — unresolvable-base fallback trusts the unverified working-copy policy, contradicting the code's own stated invariant and D10 of its plan.**
   ```go
   func CheckPolicy(ctx context.Context, root string, policy Policy) ([]Diagnostic, error) {
       base, isBoundary, baseErr := policyBase(ctx, root, policy)
       if baseErr != nil {
           if policy.Mode == PolicyModeFree {
               return nil, nil // no base to gate against, nothing declared — free
           }
           return nil, fmt.Errorf("CheckPolicy: %w", baseErr)
       }
   ```
   `policy` here is the **local, un-verified** `acdsl/policy.json` (loaded by `cmd/acdsl/main.go` via `LoadPolicy(*root)` before `CheckPolicy` is called) — the same file the function's own doc comment says a branch must not be able to weaken ("a branch cannot weaken the mode by editing or deleting the working policy.json"). If base resolution fails (no `origin/HEAD`/`origin/main`/`main`/`master` resolves, and no valid `base_ref`), the function falls back to trusting that untrusted file's `Mode` field to decide whether to hard-error. An agent on a gated/strict repo who deletes `acdsl/policy.json` (which `LoadPolicy` then reports as `PolicyModeFree`) and is in a state where base resolution also fails — e.g. a shallow clone, a repo with no `origin` remote, or a corrupted/rebased-away base ref — gets a silent pass instead of the "never a silent pass" hard error the plan's D10 explicitly requires ("an unresolvable base is a hard tool error (exit 2), never a silent pass"). This exact combination (deleted/absent policy file + unresolvable base) isn't covered by any of the `TestCheckPolicy*` tests — `TestCheckPolicyUnresolvableBase` only exercises it with an explicitly `gated` policy, not the deleted-file case. In the current worktree-pool architecture this is low-likelihood (agent worktrees are branches of a repo whose `main` is always present and resolvable), but it's a real gap relative to the stated contract and worth either closing (fail closed — i.e., treat "can't resolve base" as gated/strict whenever the base ref *ever* resolved for this repo, or simply always hard-error on an unresolvable base regardless of the local file's claimed mode) or explicitly documenting as an accepted risk.

2. **`internal/acdsl/git.go:57` — `GitChangedFiles` splits `git diff --name-only` / `git ls-files --others` output on whitespace, which breaks on filenames containing spaces.**
   ```go
   for _, path := range strings.Fields(diffed + "\n" + untracked) {
   ```
   `strings.Fields` splits on any whitespace, so a changed or untracked path like `design/ui/my screenshot.png` becomes two bogus path fragments (`design/ui/my` and `screenshot.png`), which then silently fail `os.ReadFile`/`GitShowFile` lookups in `ruleDelta` and `overlayViolations`'s caller — the rule-delta computation for that file is just dropped rather than erroring, which is a soft "check less than you think you're checking" failure mode for the very check this feature exists to make trustworthy. No file with a space currently exists in the repo (so this doesn't fire today), but the plan under this dir (`design/ui/*.png`) is exactly the kind of screenshot-heavy directory where a future filename might have one. Fix: split on `\n` instead (git's plain `--name-only`/`ls-files` output is one path per line; paths with unusual bytes are C-quoted by git by default unless `core.quotepath=false` and untouched here, so a straight newline split is correct and simpler than a `Fields` call that was presumably copied from a "trim whitespace" instinct rather than a path-splitting one).

3. **`settings/claude_code/settings.json` — the default "ask" gate on ACDSL rule-file edits was removed from smine's own settings, and this isn't called for or explained by any of the reviewed plans.**
   ```diff
   -      "Edit(**/*.acdsl)",
   -      "Edit(acdsl/**)",
   -      "Write(**/*.acdsl)",
   -      "Write(acdsl/**)",
   ```
   The acdsl-policy-modes plan's only mention of these four permission strings is as a **copy-paste snippet for a *target* repo's settings** that wants client-level strictness (`acdsl/README.md`, "Modes" section) — it never proposes removing them from smine's own default `settings.json`. Since smine itself is explicitly kept in `mode: "free"` per that plan's D8 (the generation flow needs to write to `acdsl/registry.json` on routine branches), the new `acdsl-policy-guard.sh` hook is a no-op here (it only denies writes when the local `mode` is `strict`/`gated`) — so this change actually **removes** the one guard that used to make an Edit/Write to `acdsl/rules.acdsl` or `acdsl/registry.json` in this repo require explicit confirmation, with nothing replacing it. This may well be an intentional "the new machinery makes this redundant" call, but given the repo it strips protection from is the one repo the acdsl-policy feature explicitly leaves ungated, it's worth an explicit confirm-or-revert rather than a silent side effect of an unrelated settings commit (`5c11486`, "settings: presentation profile and settings.json updates").

4. **Railroad-review's lane-context model was reversed from its approved plan without the plan document itself being updated — real but silently-tracked drift between the plan artifact and the shipped design.**
   The plan `plans/v1-2-1/2026-08-26-railroad-review-observability-wip-5158764/design/raw.md` (D1, D6, and its "Not changed" section) approves and ships **`--no-context` on the lane's Skill invocation** so lanes get *zero* doctrine injection (restoring what CTX-002 originally assumed), explicitly stating "the hooks stay as-is; the fix rides the existing opt-out token." That's exactly what version 8.3 of the skill (visible in `skills/quality/railroad-review/changelog.json`) shipped. But the code actually in this diff is **version 8.4**, which does the opposite: it removes `--no-context` entirely and instead forces *every* lane to receive the full doctrine injection via a brand-new hard-gating hook (`cmd/hooks/skill-invoke-gate.sh`) that denies every other tool call until the lane invokes `Skill(railroad-review)` and reads the injected spill in full. This is a complete reversal of the approved decision (from "minimize injection for cost" to "maximize injection for consistency, zero agent discretion") — a reasonable-sounding call given the changelog's own rationale, and it *is* transparently recorded in the skill's own `changelog.json` (version 8.4 entry) and exercised by `cmd/tests/test_skill_invoke_gate.sh` (passing) — but the plan document's own `## Changelog` table (which RULE-PLAN-047/049 says is where every post-approval plan edit must be appended) has no entry for it; the plan still reads as if v8.3/D1 is the final, current design. Anyone reading the plan alongside the code would be confused about what actually shipped and why. Recommend either updating the plan's Changelog with the v8.4 pivot and its rationale, or noting in the plan that it was superseded by a later, undocumented-at-plan-level decision.
