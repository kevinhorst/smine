### Important (Should Fix)

1. **`internal/acdsl/git.go:44` `GitChangedFiles` splits git's output on whitespace, silently mangling any path containing a space.**
   ```go
   for _, path := range strings.Fields(diffed + "\n" + untracked) {
   ```
   `git diff --name-only` and `git ls-files --others` do **not** quote spaces in paths (verified empirically: a file `dir/file with space.txt` comes back as a literal `dir/file with space.txt\n`, unescaped). `strings.Fields` splits that into three garbage tokens (`dir/file`, `with`, `space.txt`), none of which exist on disk. This feeds `ruleDelta` (`policy.go:238`), which drives the ACDSL self-management gate's added/changed/removed rule detection in strict/gated mode. A rule declaration file whose path contains a space would never be seen as "changed" by `ruleDelta`, so an edit to it in a gated/strict repo could slip past the policy check entirely (the fast-feedback hook `acdsl-policy-guard.sh` also only guards a fixed literal-path allowlist, so it wouldn't catch this either). Low probability in practice (most `.acdsl`/context files here are kebab-case), but it's a real gap in a security-relevant code path, and it's silent — no error, no diagnostic, just a missed check.
   **Fix:** split on `"\n"` and trim, not `strings.Fields`.

2. **`internal/sessions/sessions.go` `Store.Reload()` now runs unconditionally on every Sessions page view, not just on an explicit reload.** Before this diff, `s.sessions.Reload()` ran only from the (now-deleted) `POST /sessions/reload` handler; every other view read the in-memory `byScope` map populated at server start. This diff adds `s.reloadSessions()` to `handleSessionsIndex`, `handleSessionsScope`, `handleSessionsBatch`, and the new `handleSessionsArchiveTab` — so **every click into Sessions** now does a full `os.ReadDir` of every scope directory plus an `os.ReadFile` + `json.Unmarshal` of every `json/*.json` batch file across every registered repo, synchronously, on the request path. This is the opposite of the cache-invalidation discipline this same release built for the repo status cache (a cheap git fingerprint gates the expensive rescan there); here there is no staleness check at all — it's an unconditional full rescan every time. For a single-repo install with a handful of batches this is invisible; for a machine that has been running smine-nightly for months across several registered repos, batch count grows without bound and every batch/session page view will get slower over time. I could not find this decision called out in `plans/v1-2-1/session-context-report/` (the plan dir does document `s.reloadSessions()` as a new helper, but not the "call it on every read handler" cost tradeoff) — worth confirming this was a deliberate choice (freshness > cost, given local installs are small) rather than an oversight, and worth at least a cheap mtime/dir-listing short-circuit (mirroring the registry's stat-identity or the repo cache's fingerprint pattern) if not.

### Minor (Nice to Have)

3. **`internal/acdsl/git.go:78` `GitRevParse` is dead code in production.** It's called only from its own test (`git_test.go:13`); nothing in `CheckPolicy`/`policyBase`/`ruleDelta` calls it, despite the plan's Changes section speccing it as part of the git-helpers unit. Minor `ACTION-REVIEW-QUALITY-004` (no unnecessary code) violation — either wire it in where a plain `git rev-parse` is actually needed or drop it and use `shell.Run` directly in the test.

4. **Route shadow: `GET /sessions/archive` permanently hides a session scope literally named `archive`.** `internal/sessions/sessions.go`'s `validateScopeName` (and `Repo.Validate` in `registry.go`) reserve `"archived"` and `"default"` as repo/scope names, but not `"archive"`. Nothing stops a repo from being registered with `Name: "archive"` (e.g. `filepath.Base(path)` defaulting from a folder literally called `archive`), and Go's `net/http.ServeMux` will always route `GET /sessions/archive` to the new fixed archive-tab handler over the wildcard `GET /sessions/{scope}` pattern, permanently hiding that scope's own batch list. Low probability, but a one-line fix (add `"archive"` to the reserved-name check) closes it for good rather than leaving a footgun.

5. `install.sh`'s new `sed -e "s|__PEEK_HOME_ARGS__|$PEEK_HOME_ARGS|g"` (and the pre-existing sibling substitutions) uses `|` as the sed delimiter while substituting a value that could itself contain `|` on an unusual path; pre-existing pattern in this file, so not a regression, but the plist-templating additions expand its surface. Not worth a special-case fix on its own, just flagging for awareness if `PEEK_CLAUDE_HOME`/`PEEK_CODEX_HOME` ever need to accept exotic paths.

6. `plans/v1-2-1/session-context-report/` doesn't follow `RULE-PLAN-071`'s `<date>-<slug>-<state>-<hash>` directory naming that every sibling plan dir under `v1-2-1/` uses — a documentation nit, not a code issue, but it's the one plan dir I couldn't cross-reference by convention (had to grep its contents directly).
